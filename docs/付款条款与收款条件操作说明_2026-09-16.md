# 付款条款与收款条件

## 配置入口

销售 → 配置 → Production / Shipment Collection Conditions（原 Collection Terms）。客户资料 → Partner Hub 中也使用这一名称选择客户默认方案。

打开方案后，在同一表单配置：

- Required % Before Production：生产放行前要求累计收款比例。
- Cumulative % Before Shipment：发货放行前要求累计收款比例，包含定金。例如 30/70 应填写 30 和 100，不是 30 和 70。
- Invoice Payment Terms：关联 Odoo 原生付款条款，用于发票分期及到期日。它不代表实际生产或发货状态。

例如“30%定金、70%发货前”不等于“30%立即到期、70%三十天后到期”。不能用固定天数自动代替发货条件。

## 检查一张订单

打开报价单/订单 → Collections & PI：

1. Invoice Schedule 区域显示 Order Invoice Payment Terms，这是报价单顶部的同一个原生字段，不是第二套数据。
2. 下方显示客户收款方案，以及订单实际采用的生产、发货收款比例。
3. 如出现黄色提示，分别检查订单原生条款与当前方案关联的条款、账期订单是否缺少原生条款、在线预付款比例是否与生产门槛一致。

提示属于人工核对提醒，不自动阻断业务、不自动同步数据。方案后来改过，也可能与历史订单不同；这种差异不一定是错误，不要未经确认重写历史合同。没有提示也不代表合同内容已经过人工审查。

## 修改规则

- 修改报价单的原生付款条款，不改变生产和发货收款门槛，不重写已开出的发票。
- 应用收款方案时，如方案关联了原生付款条款，就复制到订单；如未关联，则保留订单已有的原生条款。
- 修改方案模板不会批量重写已有订单。符合条件的报价单可填写变更原因后点击 Apply Collection Configuration；应先检查待审核付款凭证和处理中支付。
- 已确认订单不要用修改模板来绕过改单审批。付款、凭证审核和改单流程继续使用现有入口。

本次没有为 A/B/C 类擅自生成发票到期规则，也没有改动历史订单的付款条款、比例或会计数据。
