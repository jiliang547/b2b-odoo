# Partner Hub 多语种配置与维护操作手册

适用版本：19.0.1.15.0。英文为基础语言；本次提供西班牙语 es_ES、法语 fr_FR、阿拉伯语 ar_001 的前台翻译。自定义文案使用 AI 译文，原生功能复用 Odoo 译文。

## 一、先分清三个设置

| 设置 | 控制什么 | 不会改变什么 |
| --- | --- | --- |
| 网站语言 | 客户浏览页面的语言、日期和数字格式 | 不改变公司、客户类型、商品访问权限 |
| 联系人的 Language | 客户接收支持该语言的邮件等通知时的语言 | 不给客户额外权限；不改变公司价格表 |
| 网站币种 / 价格表 | 商品使用哪套价格与币种 | 不会因为换语言而自动换币种 |

语言按钮只是选择已有译文，不是实时机器翻译。没有译文的内容回退英文。客户填写的姓名、公司名称、地址、留言不自动翻译；SKU、型号、邮箱、电话和品牌名称保留原值。注册国家和电话下拉中的国家名称沿用之前指定的英文显示。

## 二、启用本次已经提供的语言

1. 用具有网站配置权限的内部账号进入 Website → Configuration → Settings（网站 → 配置 → 设置）。多网站环境先选正确的网站。
2. 在 Languages（语言）中添加 Spanish / Español、French / Français、Arabic / العربية；系统未安装的语言先通过安装语言入口安装。
3. 网站 Default Language（默认语言）建议继续使用 English (US)。保存设置。
4. 打开前台，点击顶部语言/币种菜单，选择目标语言。检查首页、Products、注册、登录、My Account。
5. 再次浏览页面，应继续保留所选语言；手动选择 English 可以切回英文。

仅在后台激活语言、没有将其加入具体网站的 Languages，不会让该网站显示对应选项。反过来，只让菜单出现语言但没有译文，也不会自动翻译全部自定义内容。

当前项目沿用外贸网站政策，不发布中文网站语言；后台员工仍可使用中文。

## 三、部署到 Odoo.sh 后

代码仓库包含各模块 i18n/es.po、fr.po、ar.po，译文随代码部署；网站配置和商品资料属于数据库，不会随 Git 推送从本地复制到 Odoo.sh。

1. 部署包含本次改动的 Git 提交。
2. 确认 b2b_website 升级到 19.0.1.15.0，并升级 b2b_core、b2b_sample、b2b_erp_connector，以加载它们的译文。若平台未自动升级，可在 Apps 中升级对应模块。
3. 在 Odoo.sh 对应数据库的网站设置中确认语言已安装并加入网站。
4. 若语言早已安装，更新模块或通过语言管理的 Update Terms 更新译文；尽量不要勾选 Overwrite Existing Terms，以免覆盖运营人员已经校对的译文。
5. 刷新页面。JavaScript 动态文案来自部署的 PO 文件；更新代码译文后需让服务器重新加载，并重新加载浏览器资源。

不需要翻译服务 API Key，没有客户访问时逐条调用 AI 的费用。Turnstile 的 Key 和验证安全策略不因此改变。

阿拉伯语还需要运行环境具备 Odoo 原生的 `rtlcss` 工具。本地本次已安装；Odoo.sh 部署后仍需检查阿拉伯语页面实际布局和构建日志。若出现 `You need https://rtlcss.com/` 警告，应补齐环境依赖并重新生成相关前端资源，而不是复制一套阿拉伯语页面。

## 四、修改页面按钮、标题和说明

对于可以在网站翻译编辑器中选中的内容：

1. 以有网站编辑权限的账号打开目标页面。
2. 先切换到需要修改的语言，例如 Français。
3. 使用 Edit → Translate（编辑 → 翻译），选择文字并修改译文，保存。
4. 切回英文确认原文未变，再切回目标语言检查效果。

动态按钮提示、服务端错误消息等不一定能在页面编辑器中直接选中。此类内容维护在对应模块的 PO 文件中，由开发人员补充或修改后部署。不要为每种语言复制一套 XML 页面，也不要直接替换英文源码来修改法语文案。

## 五、商品、分类、品牌、FAQ 怎样翻译

这些是数据库业务内容，与页面固定标题不是同一回事。本次翻译目录包含模块自带的客户类型、FAQ、注册产品兴趣等数据；你后来在后台创建的商品、分类、品牌文案，需要给相应记录补充译文。

1. 打开产品、分类、品牌或 FAQ 的原记录。
2. 对支持翻译的字段，使用字段旁的语言/翻译入口，填写对应语言。若该表单未显示翻译入口，可用网站翻译编辑器编辑公开页面中的字段，或请管理员使用原生翻译导出/导入。
3. 优先维护商品名称、销售描述、网站描述、分类名称、品牌介绍、FAQ 问题和答案。
4. SKU、型号、数值规格、图片和附件不因语言自动变更。附件本身也不会被自动翻译；不同语言的 PDF 需分别上传并标明语言。
5. 保存后检查列表页、详情页及不同变体的显示。

必须在同一条记录上维护译文，不要为法语再建一条相同商品，否则库存、价格、订单和统计会被拆开。

对于大批商品，先用原生导出/导入机制生成待翻译数据，再交给 AI 翻译并导回；保留记录标识，不修改产品 ID、SKU 和价格。不能将本地测试库的产品 ID 直接拿去覆盖 Odoo.sh 的产品。

## 六、客户通知语言

新注册客户会把注册时选择的页面语言保存到原生联系人/用户 Language 字段。注册验证、批准和拒绝邮件使用该客户语言，不跟随后台审核人员的界面语言。

已有客户：进入 Contacts → 打开个人联系人 → 查看 Language（语言）并调整。不同表单布局可能在其他信息区域。不要仅修改公司的语言就假定所有个人联系人已同步。

客户之后临时切换网页语言不会自动修改其长期通知语言。需要改变邮件语言时，运营人员修改该个人联系人的 Language。原生订单和其他邮件还取决于各邮件模板自身的语言表达式及该语言的译文。

人工输入的拒绝原因、回复消息、订单备注不会自动转成客户语言，请运营人员直接用适合客户的语言填写。

## 七、以后新增其他语言

例如德语，需要两步，不能只做第一步：

1. 安装德语，并先在测试网站配置。
2. 导出当前自定义模块的翻译模板，补充德语 PO 译文；同时维护商品、分类、品牌等德语内容，部署并导入后实际检查，再在正式网站公开。

新增功能也应同步更新译文。开发人员可用 scripts/export_frontend_translations.py 从更新后的 Odoo 数据库导出 POT，再用 scripts/validate_translations.py 检查已有语言的遗漏、变量占位符和 HTML 结构。

POT 是英文待翻译目录，PO 是上线使用的译文。PO 中的 %s、%(request)s、#{...}、HTML 标签和链接不能随意改动，否则可能影响显示或功能。

## 八、上线复核清单

- 每种语言切换后首页、产品页、登录注册、协议、资源、FAQ、售后和个人中心均检查。
- 点击表单提交，检查必填、格式、条款未勾选、请求失败等提示。
- 确认货币、价格、MOQ、购物车和账号权限不随语言改变。
- 检查注册验证及审核邮件的正文和按钮；不要只检查主题。
- 阿拉伯语检查从右向左布局；电话、区号和邮箱仍按从左向右显示。
- 手机窄屏检查长按钮、菜单、表格和注册进度文字是否溢出。
- 译文为 AI 生成，可直接使用；正式法律条款和对外承诺建议后续由熟悉目标语言的人复核准确性。

## 九、常见问题

| 现象 | 检查方向 |
| --- | --- |
| 整页几乎不变 | 网站是否真正切换语言；自定义模块 PO 是否已部署并导入 |
| 按钮变了，商品名称没变 | 该商品记录尚未填写相应语言译文 |
| 页面翻译了，弹出的提示没变 | JS/服务端文案是否有对应 PO 译文，服务器和浏览器是否已重新加载 |
| 邮件仍是英文 | 个人联系人的 Language、模板语言和正文译文是否齐全 |
| 编辑后的译文被替换 | 是否使用了覆盖既有译文的导入/更新操作 |
| 切换语言价格看起来不同 | 先区分数字格式变化与实际币种/价格表变化；两者是独立设置 |
