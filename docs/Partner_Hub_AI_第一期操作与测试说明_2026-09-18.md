# Partner Hub AI：第一期操作与测试说明

日期：2026-09-18。模型方案：Odoo 19 原生 OpenAI。第一期范围依据开发方案第 1 节：产品推荐、技术问答、客户权限与原生价格展示、结构化项目记忆。

## 1. 本期功能边界

| 能力 | 本期实现 |
| --- | --- |
| Product Advisor | 查询当前客户可见商品、依据产品资料解释、显示原生价格/MOQ和商品详情入口 |
| Knowledge Base | 已批准 FAQ + 原生 AI 索引的产品文档检索、回答出处和原文片段 |
| 项目上下文 | 私有项目、最近问题、历史选型、独立保存的需求字段、明确编辑更正、刷新后恢复 |
| Solution Designer | 未开放；不生成正式 BOM、不计算功率或报价、不自动加购 |
| Tender Assistant | 未开放；不接收上传的 Tender、不输出投标承诺 |
| 订单/物流查询 | 后续通过受控服务扩展；本期未读取或暴露订单、付款、物流数据 |

网站前台为英文，统一为右下角悬浮聊天，不再分模式或使用独立页面。第一期通过 View product 进入现有商品详情与加购流程，不另造购物车。不是四项最终功能全部完成。

## 2. 安装与首次设置

### 2.1 部署后的最短操作

1. 将整个项目新版本部署到 SH。**不需要再到 Apps 手动安装 Partner Hub AI**：主应用 `b2b_management` 已增加 AI 依赖并提高版本号；AI 模块本身也声明随 `b2b_multicompany` 自动安装。原生 `ai` / `ai_app` 由依赖自动安装。
2. 等待 SH 构建和模块升级成功。使用有原生 **Settings / Administration** 权限的管理员登录，打开 **Partner Hub AI → Native AI Settings**。
3. 找到 **Use your own ChatGPT account**，勾选后在 Key 框填写 OpenAI API Key，点击顶部 **Save**。不是 ChatGPT 网页订阅密码；不要把 Key 发给聊天助手，也不要放进前端或 Git。
4. 打开前台，点击右下角 **AI Assistant** 悬浮按钮。客户登录后即可在同一个聊天窗口进行产品咨询和知识问答；不需要选择功能模式。旧 `/ai-assistant` 链接会转到首页并打开窗口。

安装会自动开启网站 AI 入口、关联 `Partner Hub Customer Advisor`（默认 GPT-4o）、配置每天每客户 30 次 / 每网站 300 次、每客户 50 个项目，并将初始化时该网站及全站已发布、启用的 FAQ 加入知识来源。商品与客户价格从现有系统实时读取，不需要复制商品到另一套数据库。未发布、归属其他网站的 FAQ 不会被加入；产品文件不会自动发送到外部模型。

### 2.2 哪些情况需要额外处理

- **复制正式库得到的测试库**：为防止误用随库复制的 Key，默认不允许调用。若填写并保存一个新的 Key，当前环境自动授权；若要沿用已复制的 Key，则进入 **Website AI Configuration → 点击网站名称 → Authorize AI Calls in This Test Database**，确认可能产生费用。仅保存其他设置不会绕过这层保护。
- **已有网站曾手动关闭 AI**：安装升级不擅自打开。需要使用时自行开启 Enable Customer AI；同样不会覆盖已改的 Agent 和请求限额。
- **需要 Datasheet 全文检索**：按第 3.2 节批准并索引文件；只配置 Key 不会自动把所有私有文件上传。
- **数据库运行环境**：原生 AI 需要 PostgreSQL `vector` 扩展；不支持时安装会停止，不应删除原生检查。SH 的实际环境仍需通过部署日志确认。本地原有 PostgreSQL 缺少该扩展，因此本次安装验证在独立环境完成，没有给原 8070 库安装 AI。

### 2.3 可选调整

打开 **Partner Hub AI → Website AI Configuration**，点击实际网站那一行，可调整开关、Agent 和限额。不要给网站 Agent 配置通用 Topics。计数按 UTC 日期，失败请求也占用次数；这些是请求限额，不是金额预算。新建网站会自动取得默认配置，后续升级保留运营人员已有选择。

保存在哪里：本页沿用原生 Odoo 表单。修改字段后，页面左上角会出现云朵/向上箭头样式的 **Save manually** 图标；点击它保存。菜单刚打开应先看到网站列表，点击网站名字进入，不要只勾选行首选择框。设置 Key 的原生 Settings 页面则使用其顶部 **Save** 按钮。

未配置 Key、未启用或测试环境未授权时，前台显示准备中和 Contact our team；不会调用模型，也不会展示 Key/原生异常页。自动安装本身不发送任何模型请求、不执行收费文档索引。

## 3. 放入知识库

### 3.1 FAQ（无需索引费用）

安装时已有的公开 FAQ 已自动加入，可直接在 Approved Knowledge Sources 检查或取消 Approved for Customer AI。后续新增 FAQ 按以下步骤批准；系统不会在升级时重新批准已取消或删除的来源。

1. 先在现有 FAQ 维护界面完成问答，确认类别、所属网站、Published、Active 正确。
2. 打开 **Partner Hub AI → Approved Knowledge Sources → New**。
3. 填写 Name、Website，**FAQ Question** 输入问题关键词并选择刚才的问答，选择框显示问题标题。Product Document 留空。
4. 勾选 **Approved for Customer AI**，保存。Index State 显示 Live FAQ。
5. FAQ 修改后下一次查询读取最新内容；不需要再点索引。

### 3.2 产品文件（原生向量索引）

1. 按原产品管理流程上传 Datasheet/技术说明，设置前台发布和客户可见范围。
2. 在 **Approved Knowledge Sources → New** 填写 Name、Website，Product Document 选择现有文件；FAQ 留空。
3. 勾选 Approved for Customer AI，保存，再点 **Index / Reindex Document**。
4. 本期支持非空、20MB 以内、含可提取文字的 PDF 或纯文本。扫描图片 PDF 应先转成可选中文字的资料。
5. 状态先为 Processing；原生 AI 定时任务处理后为 Indexed。后台原生来源可查看失败原因。
6. 替换原文件后会显示源文件变更、需重新索引。点击同一按钮重新索引；完成前旧内容不参与回答。

索引会把该文档内容发送给配置的模型服务。系统使用独立的私有附件副本，原商品附件及其权限不会被原生 AI 重新归属。批准知识库不等于扩大商品权限：未发布、隐藏、仅内部或不匹配客户分组的资料仍不可用。

初期请控制在每站点 500 个来源以内；这是本期检索读取上限。大量资料应在后续增加分页/后台检索任务并进行容量验收。

## 4. 客户操作

1. 登录原有客户账号，在任意网站页面点击右下角 AI Assistant。
2. 直接输入第一条问题，或点击欢迎区的建议问题。这些建议只填写输入框，不切换模式、不清空会话。
3. 输入应用场景或型号，点输入框右侧的向上箭头（Send message）。提问保存后可继续浏览。回复由原生后台定时任务生成；排队不是失败，不要重复提交。
4. 回答包括 Supporting evidence 原文、已批准资源链接、允许推荐的真实商品卡片。原生价格单独计算，AI 不负责定价。
5. 点击商品卡进入原商品详情，确认变体、数量、税费和运费后使用原购物流程。卡片金额是 MOQ 条件下的单位价格，不是最终报价。
6. 顶部 Project requirements 打开独立记忆，可检查、更正后点 Save requirements。回复生成中暂不允许修改。模型只允许从当前客户文字提取事实，不自动覆盖已经保存的要求；修改已有要求请直接编辑这些字段。
7. History 查看自己的会话，New chat 新建。右上角减号收起，方框图标展开/缩小。切换商品页、刷新、收起重开会恢复当前会话和未发送草稿；普通网页导航会重新挂载窗口，不是把网站改成单页应用。
8. Project requirements → Archive conversation → Confirm archive conversation 将项目归档，从客户列表移除。为避免重置调用限额，后台保留请求审计；不是隐私数据彻底擦除操作。
9. 页面展示最近 20 轮，推理使用最近 6 次问题/选型和全部保存需求，不无限拼接聊天记录。浏览器仅在当前标签页保存窗口状态、会话编号和短期草稿（24小时），不持久化回答/价格。退出或身份/权限变更会清除客户端私有状态。

后台要求：原生 Scheduled Actions 中 **Partner Hub AI: Process Customer Questions** 必须启用。系统提交后触发任务，并每分钟检查队列；实际等待受原生调度负载影响，不是逐字流式输出。运行中断超过5分钟、排队超过10分钟会标记失败，不自动重放不确定的收费调用；客户可再次发送或联系人工。网络断开导致提交结果未知时，使用 Retry / refresh，重复请求编号不会生成第二条调用。后台任务重启、供应商可用性仍需正式环境验收。

同公司其他联系人不能看到你的项目。Settings 管理员可在 Project Diagnostics 查看问题、状态和审计聊天以排查故障。客户审批、Segments、登录角色或商业公司变化时旧项目会被隔离，需新建项目。

## 5. 异常、费用与维护

- 超时、模型拒答、结构错误、无效出处：不展示未验证内容，页面内给出重试/联系人工的提示。
- 没找到批准资料：追问型号/场景，不凭空给出参数、认证和交期。
- 多标签页修改冲突：提示刷新，不静默覆盖需求。
- 重复请求：同一请求标识不重复调用模型；请求失败后再次提交新请求仍会计入限额。
- 同网站的提交和需求修改使用短事务互斥；模型生成已改为数据库队列和原生 cron，不再占用网页请求。不需要额外队列容器；高并发正式上线前仍须针对调度吞吐量做压力测试。
- 每次最多两个文本生成步骤和一次检索向量调用，生成单次上限 1,600 输出 tokens，检索上下文上限 24,000 字符。原生文档索引的费用和耗时另算。
- 价格、产品可见性、文档权限会在检索和结果返回时再次核验。未经授权不能通过提交别人的项目 ID 获取信息。
- 不提供任意 ORM、SQL、订单改价、收退款、审批或发货工具。外部资料只能作为内容，不会执行其中的指令。
- 严格结构和原文引用不等于证明每句解释都正确。真实模型质量、资料覆盖率和恶意提示测试仍须在配置 Key 后验收，特别是机场/消防等安全相关选型。
- 当前不承诺 SH 已验证；必须在 SH 测试分支安装并完成真实 Key/索引验收后才向客户开放。

## 6. 测试方式及上线清单

自动化测试：`custom_addons/b2b_ai/tests/test_assistant.py`，仅使用合成测试数据和模拟模型返回。覆盖私有会话、同公司不同联系人、审批变化、产品隐藏、FAQ批准、跨站点来源、引用校验、需求版本冲突、未配置Key、重复提交、供应商异常、请求配额、原生金额显示与连接上限。

浏览器测试：使用独立 `b2b_ai_test_20260918` 数据库、8072 页面，实际点击新建/发送/保存/切换/刷新，核对可用性与布局。`scripts/run_ai_ui_fixture.py` 仅为该库的 UI 测试启动器，会拦截模型调用，所有回答标有 UI TEST FIXTURE；不属于可发布插件功能，不能用于验证真实回答质量。

上线前必须完成：

- [ ] SH 测试分支安装原生 ai/ai_app 和 b2b_ai 成功，vector 可用。
- [ ] 配置真实 Key 后产品咨询成功，未配置和额度不足提示正常。
- [ ] 原生文档索引成功，文件变化后重建，文件内提示注入无权限外泄。
- [ ] 两个真实客户对同一商品展示各自正确价格和MOQ，不泄露其他公司的价格。
- [ ] 确认生成解释与引用确实相关；认证、兼容性和交期不臆造。
- [ ] 核对模型供应商数据处理、客户隐私说明、日志保留策略与内部管理员访问范围。
- [ ] 设置供应商预算告警，并验证实际响应时间和并发承载能力。

测试执行结果另在同目录的第一期验收记录中记录；不能把模拟返回测试当作真实 OpenAI 联调通过。
