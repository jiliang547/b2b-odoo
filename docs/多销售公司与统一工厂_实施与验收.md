# 多销售公司与统一工厂：实施与验收记录

日期：2026-09-14

> 最新调整：当前采用 External ERP 履约，不要求配置工厂、仓库和内部供货价，也不在 Odoo 重复确认生产或出库。初始化集中入口为 B2B Management → Business Setup。下文工厂流程及其历史验收记录仅适用于可选的 Odoo Fulfilment 模式。新版操作见《业务初始化与履约方式操作说明.md》。已有订单保留原履约模式，API 接入另行调试。

## 业务边界

一个前台网站；客户固定向一家销售法人采购。商品品牌不决定合同主体。
销售订单、PI、客户发票、收款及退款归所属销售公司；工厂拥有库存并实际出库。
销售公司使用原生 Dropship 采购向工厂进货，原生公司间规则生成工厂销售单。
一名财务可被授权访问多家公司，但不得混用日记账、银行、应收款或退款记录。

## 当前状态（开发中，不是上线验收结论）

多公司扩展 `b2b_multicompany` 已作为主应用的安装依赖，安装 B2B Management 时自动安装原生依赖、字段、视图、权限和编号，不需要运营单独安装扩展或操作隐藏开关。旧 SH 数据库部署后需要正常升级主应用，单纯推送代码不等于数据库升级。
不会自动创建五家真实法人或改写历史订单。公司名称、品牌、银行、用户权限和供货价格由运营后续配置。
网站未填写销售公司及工厂配置时，现有单公司流程不变；开始填写后自动进入多公司校验，资料不全不能跨公司下单；配置完成后自动路由，无需再次启用。尚未完成的验收分支仍不得标记通过。

## 已加入的配置入口

1. 原生公司管理：维护销售法人和工厂，不将五家公司仅作为五个 Logo。
2. 客户资料 → Partner Hub → Collection and Brand → Assigned Selling Company：在客户商业主体上设置，联系人只读继承。
3. 品牌资料 → Legal Seller → Contracting / Invoicing Company：B2B Manager 指定法人。财务再在 Receiving Accounts 关联该法人的银行日记账。
4. 网站设置 → Partner Hub → Multi-company Sales Configuration：填写 Permitted Selling Companies 和 Stock-owning Factory，并配置对应允许法人的默认 Account Brand。保存后自动使用公司路由，页面状态显示未配置/资料未完整/路由已配置；没有额外启用按钮。路由已配置不代表银行、供货价和财务设置都已完成。
5. B2B Management → Bank transfer reviews：列表增加 Company，审核表单显示公司，可按 Selling Company 分组。

不要修改客户原生 `company_id` 来代表归属销售法人；这是两种不同含义的字段。
多人权限仍使用原生用户的 Allowed Companies 与 B2B 角色，模块不会自动给员工全部公司权限。

### SH 安装与后续配置（取消单独启用步骤）

新数据库：安装 Lucky Tone B2B Management 即初始化多公司功能及依赖，不用再找 Partner Hub Multi-company Sales 单独安装。已有数据库：部署新版本后升级 B2B Management，正常模块升级会带入新的依赖。

运营按顺序准备真实销售法人和工厂 → 品牌对应法人及收款银行 → 客户归属 → 网站允许销售法人、工厂、默认品牌 → 工厂供货配置。没有真实资料的项目可以暂不填写，不会自动生成示例法人或假银行。

网站配置状态只表示路由资料是否完整，并不代替银行日记账、支付渠道、供货价和验收检查。开始配置但未配齐时禁止路由下单；配齐后自动按客户法人下单。已经产生路由订单的网站不允许直接更换库存工厂或清空路由退回单公司模式，需要先评估历史供货迁移。

空白库 `b2b_mc_install_20260914` 仅指定安装 `b2b_management`，已自动装入多公司扩展、`stock_dropshipping` 和 `sale_purchase_stock_inter_company_rules`，见 `multicompany-main-install.log`。安装过程中发现原有表格权限桥接模块无条件导入测试框架，已移除业务入口中的测试导入，交还原生测试发现机制；模块本身的测试文件保留。

## 原生供货配置

- 每家销售公司配置自己的会计、银行日记账、付款方式和订单价格表。
- 工厂配置原生仓库、公司间用户、Generate Sales order；选择生成草稿或自动确认的原生规则。
- 产品须为跨公司共享产品。在产品的采购页填写工厂供应商与内部供货单价、币种、数量阶梯和有效期。
- 对外客户价格表与内部供应商价格独立。缺少有效正数供货价时禁止安排生产，不取客户售价冒充供货价。
- 网站已路由的商品订单使用原生 Dropship 路线。销售公司的采购单与工厂销售单是内部交易，不是新增一份客户订单。
- 工厂出库与销售公司代发货记录分别是两家法人的原生库存凭据。销售方完成代发记录前必须已经存在相应工厂实际出库数量。

## 尚需处理的兼容点

原生 website_sale 明确限制网站与订单法人相同，适配模块在创建原生订单后绑定网站，不修改厂商源文件。该接入点需随 Odoo 大版本升级回归测试。

原生公司间规则不会自动修改已经确认的供货单。本模块在客户接受经许可的方案后，使用原生取消流程取消旧工厂销售单和采购单，并由原生采购规则生成替代 RFQ。内部已开票或已实际发货的情况保持拦截，不静默改写财务或出库记录。
当前不批量迁移历史品牌、银行或价格表；历史业务如需切换法人须另做迁移检查，尤其是未结清订单。

### 已确认的生产改单规则（2026-09-14）

工厂已确认生产、尚未发货时，必须由有该销售公司权限的 B2B Manager 先核实工厂允许变更，再处理供货单。

实际操作：B2B Management → Dashboard → Order changes → 打开申请 → Start Review → Edit Proposed Order → 调整商品/数量 → Save & Close → Factory Permission 页签 → 填写工厂同意人员与凭据编号 → Confirm Factory Permission → 确认弹窗 → Send to Customer。

客户同意前不取消旧供货；客户拒绝则保留旧供货。客户同意后才取消、重建。修改提案会使原许可失效，须再次核实确认。已发货或内部发票未处理不能走自动重建。

销售公司仍需要自己的原生仓库/操作类型配置以支持 Dropship 和订单库存计算，但不得将工厂实物库存放入销售公司仓库。实物库存属于工厂。
同一网站下其他法人的支付服务商保留原生公司限制：其 Website 留空，由订单公司筛选；不要强行关联另一法人的网站字段。
