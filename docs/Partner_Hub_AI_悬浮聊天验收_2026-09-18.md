# Partner Hub AI 悬浮聊天改版与验收

日期：2026-09-18。代码版本：b2b_ai 19.0.1.2.0。未推送 GitHub。

## 改动范围

- 全站右下角 AI Assistant，点击打开非模态聊天窗；展开/缩小、收起、History、New chat、Project requirements。
- 去掉客户功能模式切换和 Coming later 占位。同一会话可连续查询商品、咨询技术问题。
- 旧 `/ai-assistant` 重定向首页并打开悬浮窗，不继续维护第二套独立页面。
- 复用 Odoo 19 OWL public component、原生资源加载、原生 ir.cron。未引入 React、第三方客服后端、LangGraph 或额外生产容器。
- 请求先保存为 queued，原生后台任务领取为 running 并提交，再调用原有受控 AI 服务；用户离开页面不取消任务。运行失败/中断不会自动重放不确定的收费调用。
- 窗口只恢复当前标签页的会话编号、展开状态和24小时内草稿；回答/价格不保存在浏览器持久存储。每次从服务器读取时重新核验身份、商品权限与价格。
- 客户不需要先新建会话才能提问；未登录先引导登录。登录入口自动收起窗口，避免遮挡登录表单；认证页不会递归嵌套登录重定向。

## 测试环境与限制

在独立 `b2b_ai_test_20260918`、127.0.0.1:15432 pgvector 数据库与 http://localhost:8072 运行。原8070业务库/服务没有变更。

浏览器使用真实按钮、输入框与站内链接；没有用后台写记录代替客户发送、切页、保存需求、退出、登录等动作。

`scripts/run_ai_ui_fixture.py` 仅在上述隔离环境截获模型传输，回答标为 UI TEST FIXTURE。慢回复模拟每个生成阶段等待12秒；超时模拟抛出供应商异常。不使用真实 Key、不对外调用、不代表模型质量验收。

## 实测发现并修复

1. 初始将 owl-component 放在 wrapwrap 外，原生 public interaction 不挂载。已移入原生扫描容器，实测入口与窗口正常。
2. 无商品的空回答也调用了依赖 HTTP 请求的原生价格服务，导致非 HTTP 单元测试失败。已对空商品列表立即返回，模型后台任务不进行价格渲染。
3. 仅 Settings 权限的内部账号不能读取 B2B 应用分类，检索域因此失败。已仅在该用户有读取权时加入此可选关联条件，未使用 sudo 扩大检索权限；新增回归测试。
4. 游客聊天入口跳转登录时原窗口仍展开，且登录页再次点击可嵌套重定向。已自动收起并规范认证页的返回目标。
5. 资源区原先展示所有检索候选。现只列出回答实际引用、当前仍获授权的来源；停用来源后旧回答对应内容和链接一并过滤。
