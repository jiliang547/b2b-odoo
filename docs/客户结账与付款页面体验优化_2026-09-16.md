# 客户结账与付款页面体验优化

## 入口和使用方式

付款页的右侧操作区沿用原生 Pay Now；其下依次提供 Submit Order 和 Pay by Bank。不再显示两块独立说明卡片。移动端沿用原生结账操作区域，不新增固定悬浮层。

- Pay Now：继续原生在线付款。
- Submit Order：不付款，先提交报价供运营确认商品、运费和金额。订单生成运营待办，客户看到 Awaiting Final Quote，当前合计为估算金额。
- Pay by Bank：提交后进入 Payments & PI，按约定付款比例查看 PI、银行资料、上传凭证。
- 不要求生产前预付款的客户使用 Place Order on Agreed Terms 文案，避免误导为必须立即银行付款。

运营修改待报价订单后，继续使用 Release for Customer Payment。客户收到原生订单消息并可 Review & Pay；仍按客户的既定收款条件计算本阶段应付款，不改成强制全款。

## 精简展示

订单详情保留一行简洁付款约定，例如 20% deposit, 80% before shipment。不向客户展示内部 A/B 分类、生产/发货累计百分比解释或 ERP 接入状态。

Payments & PI 保留金额、确认收款、待审核凭证、余额、当前应付、银行资料和 PI；删除生产/发货“放行资格”的展示，防止误认为实际生产或发货已完成。真正尚未执行完成的订单修改保留简短业务提示。

上传凭证使用英文 Choose File / No file selected 和文件名展示，仍使用原生 file input；保留 PDF/PNG/JPG、8 MB 上限、服务端校验及访问控制。操作系统文件选择窗口语言由客户设备决定。

Request Change 页面复用 lt-card-body，桌面 24px、窄屏 16px 内边距，按钮窄屏满宽，错误提示也位于内容区。

## 升级说明

b2b_website 19.0.1.16.10 带有升级迁移：暂时停用两个引用旧生产提示节点的自有继承视图，在新版 XML 加载时重新启用。部署时升级 b2b_website 及 b2b_multicompany；不改历史订单金额、付款条件和会计记录。

本地升级另发现英文初始化逻辑会改写锁定的修订订单行。已将修订订单排除在该历史描述翻译任务之外，不绕过改单冻结规则。b2b_multicompany 本次版本为 19.0.1.3.8。
