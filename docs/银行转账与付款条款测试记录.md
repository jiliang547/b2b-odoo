## 1. 结论与范围

本次功能已在本地实现。最终自动回归运行 **164 项测试，0 失败、0 错误**；其中新收款功能为 25 项模型／控制器测试与 1 项真实 HTTP 上传测试。另进行了客户前台、财务后台的浏览器点击，以及实际生成 PDF 的逐页视觉检查。

## 3. 浏览器实际点击记录

### 3.1 在线定金与银行尾款混合收款

专用本地订单 **S00797**，总额 USD 100，B 类 30/70：

1. 客户前台进入订单付款入口，使用已安装的 Demo 支付完成 USD 30。
2. 前台显示已收 30、余额 70，允许生产但不允许出库。
3. 为财务 UI 测试预置一条明确标记 UAT 的尾款凭证；此步骤不是人工上传成功的证据。
4. 财务使用仅配置 B2B Finance 的临时账号，从 Dashboard 待审核提醒进入记录。
5. 点击 Register / Open Receipt，在原生付款窗口核对 USD 70、客户和 UAT 银行日记账，点击 Confirm。
6. 回到凭证记录，点击 Confirm Actual Receipt 并确认。
7. 客户前台刷新：已收 100、余额 0、允许出库，在线付款与再次上传入口不再显示。

留存记录：凭证 `BTR/2026/00001`（ID 34）；原生银行收款 `PBUAT/2026/00001`（ID 107）；演示支付交易 ID 337。

### 3.2 PI 下载和版式

客户从 **S00796** 付款页面点击 Download Current PI，实际生成并下载原生 QWeb PDF。

- 修正前横向版本保留为历史 v1；修正后 v2 为一页 A4 纵向。
- 使用 PDF 技能渲染页面图片并检查：订单明细、总额、付款门槛、已收／余额、银行说明完整，无截断。
- 对正文语言和长客户参考号换行进行了检查。
- 品牌 Logo 来自测试品牌快照，没有替换法人公司；测试素材本身为浅色 Logo，正式上线需换成适合白纸打印的品牌原图。

## 4. 本轮发现并修复的问题

1. 原生 QWeb 金额部件直接放在不支持的标签上导致付款页错误：改用支持的内部节点，并增加模板编译验证。
2. 电商购物车全额支付与分期收款不一致：复用原生 Sales 门户部分支付入口，按当前阶段计算应付。
3. 原生全局银行转账说明无法表达每单品牌账号：新流程使用订单银行快照，不混用全局银行文案。
4. 原生财务创建联系人时读取 B2B 内部价格配置受权限限制：内部同步读取使用提权；客户审批、配置写入的权限检查仍保留，并回归角色测试。
5. 原生信用计算在“按交货开票”时不包含部分未交货承诺：补入缺口，避免多个订单绕过信用额度。
6. 已收定金订单减价不能简单按订单差额退款：按实际超收计算，并核验原生退款。
7. PI 继承客户中文语言、长参考号排版及纸张方向问题：修正语言上下文、换行和纵向纸张，保持旧 PDF 不变。
8. 三项旧注册回归撞上本地历史固定邮箱：改为每次独立邮箱，不删除历史用户，不放宽注册或安全验证。

调试过程中曾使用临时测试启动器定位被测试日志捕获隐藏的断言；该启动器已移除。最终通过结果来自正常原生 Odoo 启动命令，而非修改测试结果或跳过失败断言。
