# 付款后改单操作手册

适用版本：19.0.1.15.2；更新日期：2026-09-11。

## 1. 适用范围与角色

适用于已经全额付款、尚未交付的销售订单。订单已有未完成的改单申请时，不允许重复申请；已有交付数量的订单应使用退货、换货或售后流程。

| 角色 | 操作 |
| --- | --- |
| 客户 | 提交修改要求；查看、接受或拒绝方案；支付差额 |
| B2B Manager | 审核申请、编辑草案、发送方案或拒绝申请；需要相应原生销售权限 |
| 财务人员 | 办理实际退款或账务调整，登记凭证后 Finance Complete；需要原生财务权限 |

Manager 不自动等于有权退款。实际退款沿用原生财务及支付权限，不为改单另造一套支付系统。

## 2. 客户提出申请

1. **My → Orders** 打开已付款订单。
2. 点击 **Request an Order Change**。
3. 在 **What would you like to change?** 写清原商品、目标商品、数量或费用变化；修改说明至少 10 个字符。Additional note 可补充说明。
4. 点击 **Submit Request**。
5. 系统生成 **OCR/年份/编号** 的申请，显示 Submitted。申请编号不是新订单编号。

客户后续可通过以下入口查看：

- My 首页 **Order Changes → View Change Requests**。
- My 左侧菜单 **Order Changes**；菜单收起时为历史记录图标，可先展开。
- 原订单详情中的 **View Change Requests**。该按钮在原订单存在改单记录后显示，不是只有发送方案之后才出现。

列表可能包含同公司多张订单的申请，请按申请号与原订单号定位，再点 **View →**。未付款审核订单仍在 Orders，不属于这个列表。

## 3. 运营准备草案：保存按钮在哪里

1. 后台 **B2B Management → Operations → Order Changes**。
2. 打开对应 OCR 申请，检查原订单、客户要求、金额、是否已开票或交付。
3. 点击 **Start Review**，状态变为 Under Review。
4. 点击 **Edit Proposed Order**。
5. 出现 **Proposed Revision OCR/…** 弹窗。沿用原生报价单的 Order Lines：修改商品、Quantity、Unit Price、税率及运费；用 Add a product 增加商品，行末垃圾桶移除不需要的行。
6. 检查草案总金额，点击弹窗底部的 **Save & Close**。这就是付款后草案的保存按钮；保存成功后弹窗关闭，自动回到改单申请。
7. 不保留本次编辑则点 **Discard**。不要把关浏览器、刷新页面或切换标签当作保存步骤。
8. 如不确定是否保存，可再次点击 Edit Proposed Order，核对数据，然后 Discard 关闭未作修改的窗口。

草案可能显示另一个 S 编号，这是内部修改方案使用的原生报价单，不是让客户支付的新订单。客户主订单编号不变。不要给草案单独确认销售或收款；专用弹窗隐藏了这些不适用的顶部操作。

## 4. 运营发送、客户查收

1. 运营保存草案并返回申请后，点击 **Send to Customer**。
2. 状态变为 **Customer Confirmation**，计算 Proposed Amount 和 Delta Amount，并记录发送消息。
3. 客户刷新 My 首页或 Order Changes 列表，打开对应申请，可查看 **Proposed Order** 完整明细及 **Amount Summary**。
4. 客户点击 **Accept Revised Order** 表示接受；点击 **Decline Proposal** 表示不接受。

Send to Customer 不是收款，也不会立刻改原单。客户接受之前，原订单金额、数量保持原状；已发送草案不能继续直接修改。需要另一个方案时，应先结束现有申请并重新发起，不要绕过状态限制。

如果看不到入口，确认已更新到本版本、刷新了页面、登录的是该订单所属公司账号；从 My 的 Order Changes 常驻入口查找，不要只在订单列表中寻找每一行的按钮。邮件投递依赖发信配置，站内入口不依赖邮件到达。

## 5. 客户接受后的三种结果

| 改后金额 | 接受后的处理 | 客户/财务下一步 |
| --- | --- | --- |
| 大于原金额 | Balance Due，原订单更新并暂停交付 | 客户支付差额；到账后自动完成，若已有已过账发票则仍需财务处理 |
| 等于原金额 | 无已过账发票时直接 Completed | 不再付款；已有已过账发票时进入 Finance Review |
| 小于原金额 | Finance Review，原订单更新并暂停交付 | 财务实际退款及必要账务调整后完成 |

主订单编号始终保留，Revision 记录修改次数。客户接受后已生效的修改不是简单“撤回申请”；应联系运营与财务处理，不要随意取消或删除原单。

已完成退款会扣减后续改单可使用的收款余额，不能把已经退给客户的金额再次视为可用付款。系统退款应正确关联 Refund Transaction；线下退款须在财务确认真实完成后登记凭证，不能重复登记同一笔退款。

### 5.1 增加金额：客户补差价

1. 在申请详情点击 **Pay the Difference**，进入原订单付款页面。
2. 若支付弹窗没有自动打开，点击 **Pay Now**。
3. 在 Pay Order 中核对 **Amount** 是差额，不是重新支付整个订单。
4. 选择支付方式并点击 **Pay**，等待成功跳转。
5. 回到申请确认 Completed；需要财务调整的已开票订单则按 Finance Review 处理。

实测：S00501 原额 $30.00，草案 $40.80，客户只补付 $10.80。Demo 交易成功后 OCR/2026/00077 自动 Completed，原订单仍为 S00501。

### 5.2 等额修改

客户接受后不应出现补款要求。本次 S00501 的 OCR/2026/00098 将商品数量 3 改为 2、单价 $10.80 改为 $16.20，总金额保持 $40.80；客户接受后直接 Completed。该案例没有已过账发票。

### 5.3 减少金额：先退款，再标记完成

**Finance Complete 不会自动退款，不能先点它再去付款平台操作。**

1. 财务打开申请，确认 Finance Review 和负数 Delta Amount，例如 -$11.50 表示应退 $11.50。
2. 核查原收款和原发票。已有已过账发票时，按原生会计流程处理适当的贷项通知单/补充发票及对账，不要直接篡改已过账发票。
3. 支付方式支持原路退款时，可从原订单消息里的交易编号进入 **Payment Transaction**，再点击 **Payment** 对应的付款记录，在付款记录上点击 **Refund**。
4. 在原生 Refund 向导填写正确 **Refund Amount**，不要照用默认的全额退款，确认后提交。
5. 检查退款交易确实成功。异步处理中、失败或取消不能算已退款。如果支付服务商不支持这里原路退款，则由财务在银行/支付平台完成实际退款，并保存可核验凭证。
6. 返回改单申请的 **Finance** 页签填写：
   - **Credit / Additional Invoice**：适用时关联原生账务调整单据。
   - **Refund Transaction**：有系统退款交易时，选择本订单已完成的退款交易，不能选择原始收款。系统校验客户、币种、原订单及退款金额。
   - **Finance Reference**：退款或会计凭证编号，必填；没有系统退款交易的线下处理尤其需要明确凭证。
   - **Finance Note**：说明处理方式、金额和核对情况；必要时通过附件按钮保留凭证。
7. 点击顶部 **Save manually** 保存，再点击 **Finance Complete**。
8. 客户申请变为 Completed，交付暂停解除。消息记录不代表银行到账保证；以财务核实的退款结果为准。

本次实测：S00547 从 $40.25 调整到 $28.75，OCR/2026/00099 进入 Finance Review。通过原生付款记录的 Refund 向导实际模拟退款 $11.50，生成确认成功的 **R-S00547**，关联此退款后 Finance Complete。客户刷新看到 Completed，原单仍为 S00547，总额 $28.75。

连续改单补充实测：之后 OCR/2026/00124 又把 S00547 从 $28.75 调回 $40.25，客户重新补付 $11.50 后 Completed。这验证了历史退款会正确扣减收款余额；当前测试订单最终金额为 $40.25。

## 6. 不同意修改怎么办

- 运营不同意：在申请 **Decision** 页签填写 **Rejection Reason**，再点击 **Reject**。原订单维持原状。
- 客户不接受已发送方案：点击 **Decline Proposal**，申请为 Cancelled，原订单维持原状。
- 本次实际验证 OCR/2026/00100：客户拒绝后，S00547 仍为 $28.75、商品数量仍为 2。

## 7. 实测边界

本地 8070 已实际点击验证付款前修改及支付、付款后草案保存与丢弃、发送与查收、补差价、等额完成、原生 Demo 退款、财务完成、客户拒绝。

服务端回归测试另行验证状态及权限限制，包括未审核付款拦截、普通运营不可审核、跨公司客户不可接受、已交付限制、已发送草案冻结、退款金额校验、退款不重复扣减及线下退款后的再次修改。此结果不是“全站所有行为无漏洞”的保证。

本次没有真实资金流转、没有真实邮件送达验证、没有实际交付，也没有跑正式已过账发票的会计闭环；这些应在对应环境按原生财务流程另行验收。未推送 GitHub，也未部署 Odoo.sh。
