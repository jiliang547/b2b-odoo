# 支付弹窗修复与复核

版本：19.0.1.15.1；本地 8070；2026-09-11。

## 问题证据

- 用户订单 S00497：审核已放行，未付款，金额 $30；两次演示交易停在 draft / online_redirect。
- 独立测试订单 S00499 复现同样情况：Accept & Pay → Pay 后按钮禁用、未跳转。
- 浏览器错误指向原生 PaymentForm._processRedirectFlow，对不存在的跳转表单调用 setAttribute。
- 同页还有公共脚本在译文未加载完成前操作 DOM 导致的启动错误。此问题不能只靠服务端交易状态测试发现。

## 修复方式

1. Partner Hub 页面初始化同时等待 DOM 和原生 translationIsReady，避免把尚不可求值的译文立即写入页面。
2. 在创建交易前重新调用所选支付方式的原生初始化钩子，沿用原生 direct / redirect / token 分流；不强制演示或正式支付使用同一模式。
3. 防止初始化/交易请求期间重复点击；捕获提交链路异常后恢复按钮及遮罩，并在表单内提供提示，避免依赖可能异常的全局通知 UI。
4. 未修改 Odoo 安装目录中的核心代码，未修改原订单价格、付款或审批状态。
