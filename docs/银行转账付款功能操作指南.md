# Partner Hub 银行转账付款功能操作指南

> 本版已被《银行转账付款：逐步操作手册》替代。运营请使用同目录的 [新版逐步操作手册](银行转账付款_逐步操作手册.md)，以下旧内容仅供历史参考。

版本：2026-09-14 · 适用功能版本：19.0.1.16.3  
使用人员：客户、运营人员、财务人员、仓库人员。  
本文按当前系统功能编写；英文按钮名称用于对照实际页面，不包含测试账号或测试银行资料。

## 1. 功能用途与基本原则

客户可以先提交订单，下载带品牌 Logo 和收款账户的 PI，在银行转账后上传凭证。财务核对真实到账，再使用原生客户收款记录确认分配金额。系统根据客户的付款条款，判断能否确认订单和出库。

核心流程：

客户提交订单 → 下载 PI → 银行转账 → 上传凭证 → 财务核对到账 → 登记原生收款并分配到订单 → 达到付款门槛后放行。

请务必区分：

- 上传凭证不等于实际到账；待审核金额不会计入已收款。
- 订单已确认不等于已付清；例如定金客户可以先安排生产，尾款未付清仍不能出库。
- 允许出库不等于已经发货；仓库仍须完成原生库存操作。
- PI 是付款申请文件，不是收据，也不是正式税务发票。
- 在系统登记银行收款或退款，不会自动向银行发起资金划转。

## 2. 人员分工与权限

由管理员在原生 Settings → Users 中分配角色。

| 人员 | 主要操作 | 注意事项 |
| --- | --- | --- |
| 客户 | 下单、下载 PI、银行转账、上传及补交凭证、查看付款进度 | 只能访问其有权查看的公司订单和资料 |
| B2B Manager／运营 | 配置客户品牌及付款条款，调整订单收款配置，审核改单 | 不因运营角色自动获得确认银行到账权限 |
| B2B Finance／财务 | 查看待审凭证、核验资金、登记及分配收款、退回或拒绝凭证、处理退款 | 必须依据真实银行流水，不得只看客户截图确认到账 |
| 仓库人员 | 原生库存出库、Validate | 未满足收款、信用或改单审核要求时会被拦截 |
| 会计配置管理员 | 银行日记账、科目、待收款／待付款科目等基础配置 | 日常财务审核不需要系统管理员权限 |

纯 B2B Finance 打开订单时使用只读核对视图；已有其他原生销售权限的账号可能显示更多操作。检查权限时应按账号实际拥有的全部角色判断。

## 3. 首次使用前的配置

### 3.1 设置品牌和银行账户

同一法人下的多个品牌不需要建立多个 Odoo 法人公司。操作分为两部分：先在Accounting配置实际收款账户，再到品牌页面选择这个账户对应的银行日记账。

“银行日记账”不是客户付款凭证，也不是要手工填写的流水账。它是Odoo原生的银行收款配置记录，保存账户、币种和会计设置。品牌下拉框显示的是这条记录的名称，不一定直接显示银行账号。

#### 第一步：先准备银行日记账（会计配置管理员）

1. 打开Accounting → Configuration → Journals（会计 → 配置 → 日记账）。如果看不到Configuration，请由有原生会计配置权限的管理员操作；仅有B2B Finance不一定有配置权限。
2. 先检查实际账户是否已经存在。存在时直接打开核对，不要为了关联品牌再建一个重复账户。
3. 不存在时点击New。名称建议写成“品牌名－银行简称－币种”，例如“LUCKY TONE－收款银行－USD”；此例只是命名示意，不是实际银行资料。
4. Type选择Bank；Company选择实际销售法人，不是客户的公司，也不是品牌名称。
5. 设置Currency。需要按USD收款就检查USD；若留空，系统按公司本位币判断，因此建议明确设置。
6. 在银行账户相关字段中填写／选择真实Bank Account，核对账号、账户持有人和Bank；银行的SWIFT/BIC也要维护。不同原生会计配置下，银行资料可能需要点关联账户或银行记录进一步编辑。
7. 在Incoming Payments中检查使用的入账付款方式及Outstanding Receipts；退款还需检查Outgoing Payments及相应待付款科目。科目由会计人员按账套选择，不照抄演示数据。
8. 保存日记账，记下名称。后续品牌页按这个名称搜索，而不是在品牌页重新填写银行账号。

#### 第二步：把日记账关联到品牌（B2B Finance）

1. 进入B2B Management → Operations → Brand Receiving Accounts。
2. 页面显示Product Brands品牌列表，这是正常的：此菜单复用现有品牌资料，不是单独的银行账户列表。
3. 找到要配置的品牌，例如LUCKY TONE。
4. 点击该品牌行右侧的View按钮（鼠标提示Open in form view）。不要只点名称单元格；列表支持行内编辑，点名称不一定进入完整表单。窗口较窄时可横向滚动列表查看右侧按钮。
5. 在完整品牌页面向下找到Receiving Accounts区域。它在页面下部，字段名称为Receiving Bank Journals，不在Website Content或Internal Notes文本中。
6. 点击Receiving Bank Journals右侧的空白输入区。已有选中项时，点击标签后面的空白位置。
7. 输入第一步保存的银行日记账名称；在出现的选项中点击正确记录。如果下拉只显示部分结果，点Search more...继续搜索并选择。
8. 选中后，输入框会出现一个带该日记账名称的标签。这表示已经加入待保存的关联，不能只输入名称而不选中结果。
9. 如确实需要允许另一个账户，继续点击空白处选择第二条日记账。初次配置建议每个品牌、每种币种只关联一个常用账户，避免订单初始选中非预期账户。
10. 点击页面上方的保存图标，鼠标提示为Save manually。保存后退出并重新打开该品牌，确认Receiving Bank Journals中仍显示所选标签。

这里选择的是“这个品牌允许使用的账户”。系统仍会按订单币种、销售法人等条件检查，不是选上任意Bank类型记录就一定能用来收款。

如选错，可在保存前移除对应标签再重选，或Discard all changes放弃本次未保存操作。移除品牌标签是取消关联，不等于删除银行日记账；不要随意删除原生银行资料。

#### 第三步：让客户订单使用该品牌

1. 运营在Contacts → 客户公司 → Partner Hub → Collection and Brand，将Account Brand设为刚配置的品牌，再设置Collection Terms并保存。
2. 对尚未指定品牌的新客户，由管理员在网站设置中选择Default Collection Brand作为默认收款品牌。
3. 使用一张新的订单检查Collections & PI中的Order Brand和Receiving Bank Journal，再查看客户Payments & PI中的银行指引。
4. 点击Download Current PI，核对Logo、收款户名、账号、币种及订单参考号。确认无误后才让客户转账。

仅配置品牌允许账户，不会自动把所有客户分给该品牌，也不会追溯替换旧订单银行快照。旧订单更换账户请按第9节处理。

#### 找不到或选不上时怎么排查

| 遇到的情况 | 处理方法 |
| --- | --- |
| 只有品牌名称、Tagline等列，看不到收款字段 | 还在品牌列表；点击对应行右侧View进入完整表单 |
| 进入品牌仍看不到Receiving Accounts | 核对账号是否具有B2B Finance，以及目标环境是否已安装／更新此功能；B2B Manager本身不等于财务权限 |
| 下拉框没有要用的银行 | 先到原生Journals核对记录已保存且Type为Bank，再用名称搜索或Search more...；还需有权读取对应法人资料 |
| 只看到Bank、Bank (2)等名称，不知道选哪条 | 回Journals核对对应账号和币种；让会计把名称改得清楚，不凭名字猜测 |
| 找不到Create／Create and Edit | 此处刻意禁止新建；必须先完成第一步，再返回选择 |
| 输入名称后没有出现标签 | 还没有从下拉结果选中记录；点击匹配项后保存 |
| 能关联但下单仍提示没有账户 | 检查日记账的银行账号、销售法人、币种，以及客户公司／默认品牌是否确实指向这个品牌 |
| 保存时报无权修改品牌内容 | 纯财务只维护收款关联，不同时修改Name、Logo、Tagline等品牌资料 |

带UAT、TEST-ONLY或DO NOT TRANSFER的账户是演示数据，不得用于正式收款。

### 3.2 给客户公司分配品牌和付款条款

运营进入 Contacts → 客户公司记录 → Partner Hub → Collection and Brand：

| 字段 | 填写方式 |
| --- | --- |
| Account Brand | 选择该客户用于收款和 PI 的品牌 |
| Collection Terms | 选择双方约定的付款类型和比例 |

个人联系人沿用其所属客户公司的配置。未指定品牌时使用网站默认收款品牌；未指定条款时按 A 类处理。修改公司默认配置不会自动追溯修改已经提交订单的付款比例、Logo 或银行说明。

### 3.3 维护付款条款

入口：B2B Management → Operations → Collection Terms。

| 类型 | 典型配置：生产前／出库前 | 确认订单、安排生产 | 实际出库 |
| --- | --- | --- | --- |
| A：100% 预付款 | 100%／100% | 收齐货款后 | 收齐货款后 |
| B：定金＋尾款 | 30%／100% 或 20%／100% | 达到定金比例后 | 收齐全部货款后 |
| C：100% 发货前付款 | 0%／100% | 允许先确认 | 收齐全部货款后 |
| D：账期客户 | 0%／0%，另选发票账期 | 信用检查通过后 | 信用检查通过后，可带应收出库 |
| E：特殊条款 | 双方约定的合法比例 | 达到生产前比例 | 达到出库前比例，并满足其他检查 |

注意：

- “出库前 100%”指累计收齐总额，不是在定金之外再付 100%。
- 比例必须满足：0 ≤ 生产前比例 ≤ 出库前比例 ≤ 100。
- 允许未付清出库的条款，必须选择原生 Invoice Payment Terms，用于计算发票到期日。
- 账期客户可使用原生 Customer Credit Limit；启用 Block Overdue 后还会检查逾期应收。
- Collection Terms 控制生产／出库门槛；Invoice Due Terms 控制发票到期日，两者不是重复付款要求。

## 4. 客户操作：下单、下载 PI、上传凭证

### 4.1 提交银行转账订单

1. 登录网站，选择商品并进入购物车。
2. 按现有流程核对数量、地址和配送信息，进入结账付款页面。
3. 点击 Submit Order — Pay by Bank / Agreed Terms。
4. 系统进入 Payments & PI 页面，显示订单号、付款汇总及银行信息。

以后可从 My Account → Orders 打开该订单，再点击 Payments, Bank Transfer & PI 返回此页。未确认的报价也可能在 Quotations 中查看，不应因尚未成为正式订单而重复下单。

现有在线付款入口仍保留，银行转账不是强制付款方式。若订单仍在运营审核中，应先由运营完成审核，不要绕过审核付款。

### 4.2 查看应付金额

| 页面字段 | 含义 |
| --- | --- |
| Order Total | 当前订单总额 |
| Confirmed Payments | 已确认净收款；有效退款会影响此金额 |
| Evidence Awaiting Review | 已上传、尚待财务审核的申报金额，不是已收款 |
| Remaining Balance | 当前剩余未付金额 |
| Required for Current Stage | 为达到当前生产或出库付款门槛，还需支付的金额 |
| Production: Released | 订单已确认且满足当前生产放行要求 |
| Shipment: Allowed | 满足当前出库检查，但不代表仓库已发货 |
| Shipment: On hold / not ready | 暂不满足付款、信用或其他放行条件 |

账期订单的 Required for Current Stage 可能是 0，但 Remaining Balance 仍大于 0；客户仍须按正式发票到期日付款。

### 4.3 下载 PI 并转账

1. 核对 Bank Transfer Instructions 中的收款信息、币种和 Payment reference。
2. 点击 Download Current PI，将文件提供给客户公司的财务申请付款。
3. 按当前 PI 的指定账户完成银行转账，银行备注尽量填写对应订单参考号。

如果页面要求联系运营配置账户，请先联系运营，不要使用猜测的账户或其他订单的账户付款。

### 4.4 上传付款凭证

在 Upload Payment Proof 填写：

| 字段 | 操作要求 |
| --- | --- |
| Transfer Amount | 按页面标注币种填写正数金额；非同币种转账请在备注说明实际转账币种及金额，供财务核对 |
| Transfer Date | 填写实际转账日期，不得填写未来日期 |
| Bank Reference | 填写银行流水号或可追踪的交易参考号 |
| Proof | 上传 PDF、PNG 或 JPG，单个文件不超过 8 MB，不得上传空文件 |
| Additional Information | 可说明付款用途、对应定金／尾款、汇差、手续费或其他情况 |

点击 Submit Payment Proof 后，查看 Bank Transfer History 是否出现新记录，状态为 Awaiting Finance。此时已收款不会自动增加。

若提交失败，按页面英文提示修正；重新提交前确认文件已重新选择。若网络较慢，先查看历史记录，避免把同一笔转账作为新凭证重复提交。

## 5. 财务操作：核验、登记、分配

财务审核分两步，不能只做其中一步。

### 5.1 打开审核记录并核对真实到账

1. 进入 B2B Management Dashboard，点击 Bank transfer reviews。
2. 打开 Awaiting Finance 记录，核对订单、客户、申报金额、日期、参考号和备注。
3. 查看 Evidence 附件；可在记录下方展开附件，点击图片打开原生预览。
4. 登录实际银行渠道核实资金是否到账、到账币种、金额及付款方。

客户截图只能帮助追踪交易，不能替代银行流水。不得为了消除待办而确认尚未到账的款项。

### 5.2 第一步：登记原生银行收款

若这笔流水已经在 Accounting 中登记：在 Native Bank Receipt 选择已有付款，避免重复建单。

若尚未登记：

1. 点击 Register / Open Receipt。
2. 在原生付款表单核对 Receive 方向、Customer、Amount、Date、Journal、Payment Method。
3. 金额填写银行实际到账金额，不盲目照抄客户申报金额。
4. 保存并点击 Confirm，确保付款关联的会计分录已过账。
5. 返回凭证审核记录，核对 Native Bank Receipt 已关联；必要时重新打开记录刷新。

这一步是登记已经收到的款，不会向银行发起收款请求。

### 5.3 第二步：确认分配到此订单的金额

1. 核对 Allocated Amount (Receipt Currency)，填写本笔收款用于此订单的金额。
2. 必要时填写 Review Note；若实际到账账户与订单指定账户不同，必须说明原因。
3. 点击 Confirm Actual Receipt。
4. 确认提示，核实状态变为 Receipt Confirmed。
5. 核对客户页面的已收款、余额及放行状态，并确认看板待办减少。

系统会检查付款方向、客户公司、销售法人、银行日记账、已过账状态及可分配金额。在线支付关联的原生付款不能再次作为银行转账重复计款。

### 5.4 部分到账、超付和币种差异

- 少到账：只按实际收到且分配的金额确认，余款由客户补付。
- 多到账：本订单分配金额不得超过剩余应付；超出部分留作原生客户未分配余额，由财务另行处理。
- 一笔流水用于多个订单：使用同一原生付款分别分配，累计不得超过实际收款总额。
- 实收币种与订单不同：分配字段按原生付款币种填写，系统按付款日期的原生汇率换算为订单币种。
- 手续费、汇差和发票核销：继续使用原生 Accounting 流程，不通过虚增申报或分配金额抹平差额。

## 6. 材料不完整或不认可时如何处理

| 情况 | 财务操作 | 客户结果 |
| --- | --- | --- |
| 凭证模糊、缺少银行流水号等 | 填写 Review Note → Request More Information | 显示 More Information Required 和原因，可重新上传 |
| 凭证不属于本单、无法认可等 | 填写 Review Note → Reject | 显示 Rejected 和原因，不计入已收款 |
| 仅等待银行实际到账 | 暂不确认到账，跟踪银行流水 | 仍为待审核，不应视为已付款 |

客户补交是在同一订单产生新凭证记录，不覆盖旧记录。财务审核新记录时先检查是否已有原生收款，避免再次登记同一笔钱。

## 7. 完整示例：USD 1,000，定金 30%＋尾款 70%

| 阶段 | 操作 | 已收款 | 剩余未付 | 预期状态 |
| --- | --- | --- | --- | --- |
| 提交订单 | 客户选择银行／约定条款下单 | 0 | 1,000 | 当前需付300，尚不满足生产门槛 |
| 上传定金 | 客户转账300并上传凭证 | 0 | 1,000 | 待审核300，尚不算到账 |
| 定金确认 | 财务登记Receive300并确认分配300 | 300 | 700 | 满足生产门槛，尾款未齐不能出库 |
| 上传尾款 | 客户转账700并上传新凭证 | 300 | 700 | 待审核700，仍不能按付清出库 |
| 尾款确认 | 财务登记Receive700并确认分配700 | 1,000 | 0 | 满足付款方面的出库门槛 |
| 仓库出库 | 仓库完成原生出库单并Validate | 1,000 | 0 | 出库完成后客户可见Shipped |

如果第一笔只到账200，即使客户申报300，也只能确认实际200；需要再收100才能达到生产门槛。其他未完成的改单审核等条件仍可能阻止出库。

## 8. 出库、正式发票与对账

1. 仓库使用原生 Inventory 出库单，核对商品及实际数量后点击 Validate。
2. 系统再次检查付款、信用及相关审核条件；被拦截时回到订单与收款记录查原因，不绕过检查。
3. D／允许欠款发货的 E 类，出库时按原生开票政策生成并过账应收发票，并安排会计复核；开票数量仍受商品开票政策影响。
4. A／B／C 使用正常销售开票流程，PI 不能代替正式发票。
5. 财务继续完成银行对账及收款与对应发票的核销。

未生成正式 PDF 的原生发票网页可能显示 Invoice Preview。这是发票预览，不是订单 PI，也不能据此认定账务未过账；账务状态以原生发票 Posted 等状态为准。

撤销有效原生收款会影响后续订单收款与放行判断，但不会自动撤回已经完成的实物出库。不得通过修改已审核付款的金额、客户或币种来改账。

当前出库在 Odoo 内完成；外部 ERP 出库接口不属于此功能已经接通的范围。

## 9. 更换收款账户、品牌和 PI

由 B2B Manager 打开具体订单 → Collections & PI：

1. 填写 Reason for Configuration Change，说明为什么要调整。
2. 在 Order Brand／Receiving Bank Journal 选择获准使用的品牌和银行。
3. 保存，核对新的银行说明和 Logo 快照。
4. 通知客户重新下载 Download Current PI，按最新资料付款。

注意：

- 有处理中在线付款或待审凭证时，应先处理完再更换账户。
- 已确认订单的付款比例冻结；不能用更换公司默认值绕过冻结。
- 草稿／报价可按允许范围调整配置；Apply Collection Configuration 用于按当前选择重新取配置。
- Issued PI Versions 保留历史 PI。资料变化后生成新版本，不覆盖旧版本；资料未变时重复下载不会无意义地生成新版本。
- 订单账户变更不意味着历史正式发票银行已自动改好。财务须另行核对 Recipient Bank；已签发文件不得静默覆盖。

## 10. 已付款订单修改与退款

客户发起 Request an Order Change 后，沿用运营审核提案、客户接受／拒绝流程，正式订单号不因修订而另换。

| 原已收款 | 修改后订单总额 | 处理方式 |
| --- | --- | --- |
| 300 | 800 | 不退款，仍需付500 |
| 300 | 200 | 实际应退100 |
| 300 | 1,200 | 按原付款比例检查是否需补定金；出库按新总额检查 |

银行退款步骤：

1. 财务核对改单申请的实际应退金额；有正式发票的，按会计要求处理贷项通知单或其他调整。
2. 在实际银行完成退款。
3. 在 Accounting → Customers → Payments 使用原生 Send 客户付款登记真实退款，并确认已过账。
4. 回到改单申请，关联 Bank Refund Payment，填写 Finance Reference 及说明。
5. 点击 Finance Complete，核对申请完成及客户净收款变化。

仅填写文字参考号不能完成退款。退款必须匹配客户、法人及实际应退金额；同一退款不能重复用于多个已完成申请。完成后不能替换退款证据。

如使用线上退款，应关联有效且已完成的原生 Refund Transaction，不能同时再选银行退款重复扣款。本功能不会仅因点击 Finance Complete 就自动调用银行或支付平台退款。

## 11. 常见问题排查

| 现象 | 优先检查 |
| --- | --- |
| 看不到上传入口 | 是否仍有余额、是否启用订单收款流程、银行是否已配置、订单是否取消或仍待运营审核 |
| 上传后已收款没有变化 | 正常；需要财务登记原生收款并执行Confirm Actual Receipt |
| 提示文件格式／大小错误 | 是否为PDF/PNG/JPG、是否空文件、是否超过8MB；仅修改文件后缀不能变成有效图片 |
| 提示先选择原生银行收款 | Native Bank Receipt是否关联，不可仅凭附件确认 |
| 提示先过账 | 检查原生付款关联分录以及Outstanding Receipts配置 |
| 提示分配超额 | 本次分配是否超过订单余额，或同一流水是否已分配给其他订单 |
| 已付定金仍不能出库 | B类需要收齐尾款；同时检查信用和改单审核状态 |
| 账期订单还欠款却允许发货 | 可能符合D/E约定；剩余款项按正式发票到期日收取 |
| 不允许更换银行账户 | 是否有待审核凭证或处理中支付，是否缺少变更理由 |
| 退款不能完成 | 是否已有正确原生退款记录，而不只是填写参考号 |
| 发票账户与订单不同 | 财务核对历史发票Recipient Bank和当前订单；不要让客户在未澄清前转账 |

## 12. 上线及日常检查清单

上线前确认：

- 真实公司法律名称、地址及英文报表资料已填写；没有示例网址。
- 品牌Logo、银行账户、币种、默认品牌及客户条款均正确。
- 财务权限、银行日记账及会计科目已配置，邮件发送正常。
- 目标环境中不存在被误用的TEST-ONLY演示收款信息。
- 本地数据库配置不会随Git代码自动同步到Odoo.sh，应在目标数据库重新核对。

日常财务检查：

- 查看Bank transfer reviews待办，及时处理客户已上传材料。
- 核对银行流水与原生付款，避免重复登记及遗漏分配。
- 关注账期到期应收、待退款申请及已退回但客户尚未补交的材料。
- 完成原生银行对账、发票核销，并保留全部审核和附件记录。

本地验收使用过模拟银行收款及Demo支付，不代表真实银行或支付平台的资金链路已完成生产验收。
