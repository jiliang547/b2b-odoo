# 银行转账、客户付款条款与品牌 PI 操作说明

版本：2026-09-14；适用：Partner Hub 19.0.1.16.3（含收款角色访问、退款凭证校验及展示修复）。

报表配置提示：原生尚未生成正式PDF的发票网页会标注Invoice Preview；这不是订单PI，也不表示账务未过账。正式文件仍使用原生发票发送／生成流程。部署其他数据库后，在原生公司／Document Layout核对英文Company Details、页脚、真实公司网址；Git代码不包含本地报表配置。历史发票银行需要财务逐张核对Recipient Bank，不批量改账或覆盖已签发文件。

## 本次更新：退款与凭证补交

- 减价不一定退款。例如订单已收 30，总额从 100 改为 80，只需再收 50；总额改为 20，实际应退 10，不是退订单差价 80。
- 退款申请进入 Finance Review 后，仅填写 Finance Reference 不能完成退款。银行退款必须先在原生 Accounting → Customers → Payments 新建 Send 客户付款，核对客户、金额、币种、银行并确认，使关联会计分录已过账，再在改单申请的 Bank Refund Payment 选择该笔退款，填写参考号及说明，点击 Finance Complete。
- 在线退款使用已成功完成、属于原订单的原生 Refund Transaction。银行退款和在线退款只能选一种证据；同一笔退款不能用于另一份已完成申请。此功能不代替财务实际银行转账，也不表示会自动向支付服务商发起退款。
- 缺少有效原生退款证据时，申请不能完成、发货继续受控。完成后不能替换退款证据。历史曾错误标记完成但缺少实际退款的记录，需要财务核对处理，不应通过修改参考号或重复完成来掩盖。
- 财务需要客户补材料时，在付款凭证填写原因并选择 Request More Information。客户在 Payments & PI 看到原因，重新上传形成一条新记录；旧记录保留。只有新凭证关联原生实际收款并由财务确认后才计入已收款，退回及待审核凭证不算到账。
- 运营更换订单收款账户需要填写理由；存在待审核付款凭证或支付审核时先完成审核。客户重新下载当前 PI 会生成新版本，旧 PI 保留原银行信息，不覆盖历史文件。

权限说明：B2B Manager 应用收款政策不需要另加会计权限。仅具有 B2B Finance 的账号打开订单时使用只读核对视图，查看商品、金额、收款、发票与 PI；不授予其报价计算器或项目销售权限。已有销售权限的账号仍使用原生完整订单表单。新生成发票沿用订单选择的收款账户，历史已开发票须财务核对后更正，不自动批量改写。

## 1. 先理解三个独立状态

订单确认、实际收款、允许出库不是同一件事。上传凭证只产生待审核记录，不会增加已收款，也不会自动放行。

| 条款 | 确认订单／安排生产前 | 实际出库前 | 原生应收 |
| --- | --- | --- | --- |
| A：100% 预付 | 收齐 100% | 收齐 100% | 按正常开票流程 |
| B：定金＋尾款 | 达到定金比例，如 30% 或 20% | 收齐 100% | 按正常开票流程 |
| C：发货前全付 | 可以不付款先确认 | 收齐 100% | 按正常开票流程 |
| D：账期 | 信用检查通过即可确认 | 信用检查通过即可出库 | 出库时生成并过账原生发票，按付款条款到期 |
| E：特殊条款 | 使用审核确定的生产前收款比例 | 使用审核确定的出库前收款比例 | 如允许未付清出库，必须选择原生发票付款条款 |

这里的“生产放行”指允许确认销售订单并进入原有采购／库存流程，不会凭空建立一套生产模块。商品实际生产仍按你配置的原生路线执行。

## 2. 一次性配置

### 2.1 权限

- 管理员在原生 Settings → Users 中分配权限，无需重复维护另一套账号系统。
- B2B Manager：配置客户所属品牌、客户付款条款和订单上的收款安排。不自动获得银行到账审核权。
- B2B Finance：审核银行凭证，使用原生客户收款，并维护已有品牌与银行日记账的关联；不能因此审批客户或修改商品品牌文案。
- 创建银行日记账、配置科目表与待收款科目，由具有原生 Accounting 管理权限的人员完成。财务审核员不需要为了确认一笔款而获得系统管理员权限。
- 仓库人员仍使用原生库存权限；付款不满足条件时，Validate 和实际出库完成环节都会拦截。

### 2.2 五个品牌与银行账户

同一法人仍只使用一个 Odoo 公司；不要为了五个品牌新建五个法人公司。

1. 在原生 Accounting → Configuration → Journals 建立相应的 Bank 日记账。
2. 填写正确的银行账户、收款户名、银行、SWIFT/BIC、币种及法人公司。
3. 在入账付款方式中配置 Outstanding Receipts 科目。否则单纯把付款状态改为处理中，并不一定有已过账的会计分录，审核会被拒绝。
4. 财务进入 B2B Management → Operations → Brand Receiving Accounts，打开已有品牌，在 Receiving Accounts 关联该品牌允许使用的银行日记账。
5. 品牌 Logo 继续使用现有品牌 Logo 字段；收款映射不会更改产品所属品牌。
6. 管理员在网站设置中选择 Default Collection Brand，作为没有指定品牌的新客户默认值。

账户按订单币种匹配。有多个同币种合格账户时，初始选择按记录顺序确定，运营应检查订单的具体账户。建议每个品牌、每个收款币种只配置一个常用账户，其他情况在订单上明确选择。没有匹配账户时，不展示虚构账号，客户会看到联系运营的说明。

### 2.3 给客户公司设定默认值

Contacts → 打开客户的公司记录 → Partner Hub → Collection and Brand：

- Account Brand：客户收款和 PI 使用的品牌。
- Collection Terms：A、B 30/70、B 20/80、C、D 或已配置的 E。

个人联系人下单时取所属公司的设置。未配置付款条款时使用 A。修改公司默认值不会追溯修改已提交订单的比例、Logo 或银行说明。

Collection Terms 的维护入口：B2B Management → Operations → Collection Terms。发票 Payment Terms 只负责到期日期，不能替代“生产前／出库前收款比例”。

账期客户如需额度限制，应启用原生 Customer Credit Limit 并设置客户额度；系统复用原生应收和待开票额度计算。勾选 Block Overdue 后，有逾期未核销应收也会拦截。未设置额度不等于自动获得一个系统推算的额度。

## 3. 客户下单与付款

### 在线付款

保留现有在线支付。B 类订单在原生订单付款窗口可选定金或全额；收款统计只计实际完成的支付，不把“授权成功”当作已到账。

### 银行转账或约定账期

1. 客户在结账页选择 **Submit Order — Pay by Bank / Agreed Terms**。
2. 进入订单 **Payments, Bank Transfer & PI**。
3. 查看订单总额、Confirmed Payments、Remaining Balance 和 Required for Current Stage。
4. 点击 **Download Current PI** 下载带订单品牌和收款账户的 PI，交给自己公司的财务。
5. 客户在银行完成实际转账后，填写金额、日期、银行参考号并上传 PDF／PNG／JPG 凭证，单个文件不超过 8 MB。
6. 点击 **Submit Payment Proof**。状态为 Awaiting Finance；系统会明确提示，上传凭证尚不代表收到款。

PI 是付款申请文件，不是收据，也不是税务发票。历史已发出的 PI 不覆盖；订单金额、已收金额或收款安排变化后，可下载新版本。

“先提交给运营改商品／价格”的原有 Submit for Review 入口仍保留；运营释放前不能发起付款或上传到账凭证。

## 4. 财务审核：务必做这两步

### 第一步：登记实际收款

1. B2B Management Dashboard → **Bank transfer reviews**，或 Operations → Bank Transfer Reviews。
2. 打开待审核记录，核对附件和银行真实入账流水。客户申报金额不等于实际到账金额。
3. 已有原生付款记录：在 **Native Bank Receipt** 选择它，避免重复登记。
4. 尚无原生付款记录：点击 **Register / Open Receipt**。
5. 在弹出的原生付款单中，核对 Customer、Amount、Date、Journal、Payment Method，点击 **Confirm**。此处只是登记已在银行收到的钱，不会向银行发起一笔转账。
6. 新建付款会关联回审核单。需要时重新打开审核单刷新显示。

### 第二步：把实际金额分配到订单

1. 核对 **Allocated Amount (Receipt Currency)**，这是分配到此订单的金额，不一定等于整笔银行流水金额。
2. 点击 **Confirm Actual Receipt** 并确认提示。
3. 只有与客户、法人和付款方向一致，且有已过账会计分录的原生银行收款才可确认。
4. 实际收到其他账户时必须写明 Review Note；不能用别家客户的款给本客户认领。

允许分次收款：例如 100 元订单采用 30/70，先收到 20 元不会放行；再收到 10 元才达到生产门槛；收到最后 70 元才允许出库。

同一笔付款不能重复超额分配。超付部分保留在原生客户余额中，不强行算入已超额付清的订单。非订单币种的实际收款，按原生付款日期的汇率换算成订单币种。

看不清或缺资料：填写 Review Note → **Request More Information**；不认可：填写原因 → **Reject**。客户可提交新的补充凭证，旧记录保留。

## 5. 发票、核销与出库

- 到账确认后，客户页面会更新已收款、余额和出库资格；客户也可在订单沟通记录中看到通知。
- 到账审核不代替原生银行对账与发票核销。财务仍需在 Accounting 中把客户收款匹配到对应发票，处理手续费、汇差或银行对账单。
- D／允许欠款发货的 E 类订单，实际出库完成时会调用原生开票并过账，产生原生应收和到期日，并安排会计复核活动。开票范围仍遵循商品原生开票政策；需要分批按实发数量开票，应使用 Delivered quantities。
- A／B／C 按正常销售开票流程操作，不以 PI 代替正式发票。
- 财务撤回已确认的原生收款后，该款不再计入订单已收金额，未满足付款条件的后续出库会被拦截。已经发生的实物出库不会被自动撤销。
- 当前库存操作在 Odoo 中执行；没有在本次新增外部 ERP API 调用。以后 ERP 出库接口应调用同一放行检查，不应直接修改数据库状态绕过它。

## 6. 修改订单的收款账户

由 B2B Manager 在订单 **Collections & PI** 填写 Reason for Configuration Change，再选择 Order Brand／Receiving Bank Journal 并保存。系统同步生成新的银行说明和 Logo 快照、记录变更并通知客户重新下载 PI。

有处理中在线付款或待审核凭证时，先完成或处理这些记录，再改账户。确认后的订单付款比例冻结；仍可有理由地改为财务已批准的其他收款账户。取消订单不能再调整。

草稿／报价阶段修改付款条款后，保存即同步生效；**Apply Collection Configuration** 用于按当前选择重新取配置。不要把“改了公司默认配置”理解为“旧订单自动改条款”。

## 7. 部分付款后的改单与退款

沿用 Request an Order Change → 运营审核提案 → 客户接受／拒绝的既有流程，不生成新的正式订单号。

- 100 元订单已收定金 30 元，减到 80 元：已收仍为 30，尾款变 50，不退款。
- 已收 30 元，减到 20 元：实际需要退 10 元，不是退订单差价 80 元。
- 增价后，按照这张订单的原付款比例检查是否需要补充定金；出库仍按新的订单总额检查。
- 银行收款发生退款时，财务先完成真实退款并登记原生客户付款（Send／Outbound），在改单申请填写 Bank Refund Payment 和 Finance Reference，再完成财务审核。退款必须匹配客户、公司和实际应退金额，不能复用同一笔退款。
- 已开正式发票的调整仍需财务处理原生贷项通知单／补充发票；操作记录和原付款不会被覆盖。

## 8. 上线前检查

真实品牌 Logo、银行账号、币种、默认品牌、付款条款、科目表／待收款科目、财务人员以及邮件发送配置都需要在目标数据库填写或核对。本地的 UAT Bank / TEST-ONLY 记录只供演示，不能用于收款。
