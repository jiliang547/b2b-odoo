# 用友 C4 销售订单对接操作说明

日期：2026-09-23。适用：Partner Hub Yonyou Connector 19.0.1.2.0。含客户业务员分配。

## 1. 本期实际范围

网站原有付款、银行收款审核、客户付款条款不变。原生报价单真正变成销售订单（`sale`）时，后台排队创建用友销售订单。ERP 故障不回滚已经确认的客户订单或支付结果。

本期仅向测试组织 **999** 写入；接口配置同时启用测试限制。不会自动补传旧订单，不会自动审核 ERP 订单，也不代表工厂开始生产。改单、取消和物流状态回传尚未接入；原订单变更后提示人工处理，不会另建一张 ERP 订单代替原单。财务凭证、收款记账不传 ERP。

网站配送地址、客户备注尚未新增专门的 ERP 字段映射；ERP 人员审核开立单时仍需核对收货信息、电源插头和工作电压，不应把接口创建成功当成可以直接发货。

## 2. 管理员一次性配置

1. 打开 **B2B Management → Configuration → Yonyou ERP Mapping**。
2. 保留 **Restrict All Organizations to 999** 勾选。Management Org、Default Use Org、ERP Sales / Invoice / Stock Organization 均填写 `999`。
3. 在现有连接中配置 App Key / App Secret，勾选 **Enable Mapping Queries**。密钥只允许系统设置管理员查看和修改，不要发给客户、放入代码或截图。
4. **USD to CNY Interface Rate** 初始为 `6.30000000`，可以修改。它只用于本接口新确认订单；不修改原生会计汇率，也不重算已确认订单。
5. 完成后面客户、产品、税务检查，再勾选 **Send Newly Confirmed Orders to ERP**，点击原生保存按钮。

**Create / Verify ERP Customer on Approval** 是注册审批同步客户的独立开关，不等于销售订单开关。安装/升级模块不会擅自打开自动下单开关，也不会复制本地数据库中的连接密钥到 Odoo.sh。

本期无法通过取消测试勾选而向正式组织下单；正式切换需单独验证并开放。

## 3. 运营检查客户

以下操作需要 **B2B Manager**，且员工有权操作客户所属销售公司。右上角多选负责的公司即可；验证组织按配置和客户销售公司确定，不靠运营当前公司来猜。联系人不单独分配ERP业务员。

### 3.1 ERP 已有客户：输入客户编码，自动带出负责人

1. 打开 **B2B Management → Business Data → Customers**（或 Contacts），进入下单客户所属的**公司档案**，不要选择其下的个人联系人。
2. 点 **Partner Hub** 页签，检查 **Collection and Brand** 中的 **Account Brand / Assigned Selling Company**。这里的销售公司是签约收款主体，不是客户自己的法人，也不是ERP统一测试组织。
3. 找到 **ERP Customer Code**，填写ERP客户编码，例如 `LT2026030311`。
4. 点击客户编码旁的 **Verify & Refresh**。按钮会先按原生机制保存表单，再查询ERP；查询成功显示客户名称、ERP组织和绑定状态。
5. 查看新字段 **ERP Salesperson Code / Name**、**ERP Department Code / Name**。例：上述客户在本次测试时返回 `LQSTEST / 吉亮`、`cs / 销售部`。业务资料后续以ERP实时结果为准。
6. 已绑定客户的业务员、部门是只读的。要换业务员，先在ERP客户的目标使用组织中更改默认负责人，再返回这里点 **Verify & Refresh**。
7. 查看 **ERP Order Currency**：ERP交易币种未维护时使用USD，维护了则按ERP。配置同币种的网站价格表，不要把注册资金币种当成交易币种。

**三个按钮不能混淆：** 分类编码旁的 **Verify** 只验证分类，例如 `06 LUCKY`；客户编码旁的 **Verify & Refresh** 查询具体客户并带出负责人；未绑定客户或注册审核上的 **Verify Salesperson** 验证手工输入的业务员及部门。仅保存编码不等于验证成功。

### 3.2 自然流量新注册客户：审核时指定业务员

客户先完成注册和邮箱激活。运营进入 **B2B Management → Operations → Pending Registrations**，打开申请：

1. 检查客户名称、国家、邮箱、电话、客户价格类型等审核资料。
2. 若ERP已有该客户，使用 **Link Existing Company**；先按3.1完成公司绑定，再关联。不要为了分配业务员重复创建ERP客户。
3. 确实是新公司时，**Company Resolution** 选 **Create New Company**。
4. 在 **ERP Customer Mapping → Account Brand** 选择品牌。系统带出品牌默认客户分类、业务员和部门，作为这次申请的初值。
5. 核对 **ERP Customer Category Code**，点旁边的 **Verify**。
6. 在 **ERP Salesperson Code** 输入要分配的业务员编码，允许覆盖品牌默认值。**ERP Department Code** 输入其部门编码；若不确定，可清空部门再验证，系统只在目标组织下找到唯一有效部门时自动填入。有多个部门时必须明确选择编码，不自动挑第一项。
7. 点 **Verify Salesperson**，核对姓名、部门名称和 **Salesperson Verification = Verified**。修改编码后需重新验证。测试组织999的已实测组合为 `LQSTEST / cs`；不是要求所有真实客户都分配给这个人。
8. **ERP Customer Code (blank = generate for new company)** 可以留空，系统生成稳定测试编码。
9. 点击 **Approve & Activate**。系统再次实时核验负责人 → 创建ERP客户 → 查回确认负责人、部门等与审核资料一致 → 创建并绑定Odoo公司 → 完成原有审批。
10. 打开新公司的 Partner Hub，负责人已变为ERP回传的只读资料。以后下单使用这个ERP客户在目标使用组织下的默认负责人，不取审批操作员，也不会被品牌后来换人直接覆盖。

**不要先批准再去分配业务员。** 注册审核时正式公司可能尚未创建，因此此次分配入口就在申请内。对手工创建的未绑定公司，Partner Hub也允许输入和验证人员，但该操作只保存本地预设，不会创建/覆盖ERP客户，也不会自动批准某份注册申请。

### 3.3 品牌默认负责人：少填重复信息

打开 **B2B Management → Configuration → Product Brands**，找到品牌行，点右侧 **View / Open in form view** 打开完整表单，而不是停留在行内编辑。设置 **ERP Salesperson Code / ERP Department Code**，点击 **Verify Salesperson** 核对，最后保存。

品牌默认值用于新申请选择品牌时预填。每个申请可单独修改；品牌默认值改变不重分配已有客户，也不静默更改正在审核或已经冻结的创建请求。每个ERP业务员不需要额外开通一个Odoo登录账号。

### 3.4 验证失败时怎么处理

| 情况 | 处理 |
| --- | --- |
| 员工不存在、停用或未标记业务员 | 到ERP核对人员编码、状态和业务员属性，再验证 |
| 目标组织下没有有效任职，或部门编码不匹配 | 核对员工在目标组织的主职/兼职及有效日期；不要直接套用其他公司的部门 |
| 同一组织存在多个可用部门 | 人工填写正确的 ERP Department Code 后重新验证 |
| HTTP 403 / 接口无权限 | 给当前用友应用授权下述三个只读接口，刷新凭证后重试；不能跳过验证 |
| 创建已尝试、负责人输入框只读 | 这是防重保护；先查询该ERP客户，处理不确定结果，不复制申请另建客户 |
| ERP创建成功但负责人不一致 | 保持待审核，人工核对ERP已有档案；不再创建第二个客户 |

管理员需授权：[员工详情查询](https://open.yonyoucloud.com/#/doc-center/docDes/api?apiId=57a419ce100a471cb42d25f01a0665c8&isOrigin=1&selectApiTab=open) `/yonbip/digitalModel/staff/detail`、[部门详情查询](https://open.yonyoucloud.com/#/doc-center/docDes/api?apiId=b357528574fa41d982ed6c0d95850937&isOrigin=1&selectApiTab=open) `/yonbip/digitalModel/admindept/detail`、[业务单元详情查询](https://open.yonyoucloud.com/#/doc-center/docDes/api?apiId=9abe743973574ae088a85b1b0d9e2b84&isOrigin=1&selectApiTab=open) `/yonbip/digitalModel/orgunit/detail`。这些查询不新建员工、不修改组织，也不保存员工的身份证、银行账户等无关信息。

## 4. 税费：复用 Odoo 原生税和财政位置

约定：商品及价格表单价**不含税**，结算展示未税金额、税额、应付总额。中国大陆客户 13%，其他国家/地区 0%。这里是本项目已约定的接口规则，不替代企业税务判断。

### 会计管理员先设置销售公司的税规则

1. 在右上角选择要配置的**销售公司**为当前公司。
2. 打开 **Accounting → Configuration → Taxes**，检查产品销售税为百分比税，价格不含税。按需要准备本公司的 13% 和 0% 销售税。
3. 打开 **Accounting → Configuration → Fiscal Positions**，设置客户适用的原生税替换规则。例如产品默认 13%，出口客户通过财政位置映射为 0%。Odoo 19 的税替换项关联原税和适用财政位置，不能只新建一个空名称就认为映射完成。
4. 各销售公司的税和财政位置分别配置，不把 A 公司的税直接用于 B 公司的订单。

### 运营给客户选择

在客户公司 **Partner Hub → Customer Tax Rule (Selling Company)** 选择上述财政位置并保存。此字段是原生客户财政位置在其 Selling Company 下的快捷入口，不是第二套税务配置；客户联系人创建报价单时沿用该公司税规则。

ERP 中国大陆客户必须对应 13% 的不含税销售税；非中国大陆客户可使用 0% 税，也可使用原生无税。复合税、含税价、负数收费、预付款发票行等不在本次传单范围内，遇到时会阻止传单并要求人工核对。

**重要：修改客户税规则，不代表已确认、已付款的旧单会被自动重算。** 新报价先检查订单行税率及合计，确认后才交客户付款。

## 5. 产品与运费

1. 打开产品资料 → **Partner Hub → ERP Material Mapping**。
2. 填 ERP 物料编码，选择有权操作的验证公司，点击 **Verify**；多变体到各变体的 **ERP Mapping** 页分别填写。
3. 核对一个 Odoo 产品基础单位与一个 ERP 基础单位代表相同数量。箱/件不能只因编码存在就混用。订单采用其他 Odoo 单位时按原生单位换算为产品基础单位再传输。
4. 旧映射需重新 Verify 一次以记录单位校验信息。修改基础单位后也需重新验证。
5. 运费建立为 Odoo 服务产品（例如 Freight），绑定真正的 ERP 运费料号并验证。运营在报价单中追加数量 1、正确金额和税率即可；接口按普通明细传输，不再额外加一次运费。

## 6. 每张订单怎样操作

### 客户直接付款

客户按原流程结算 → Demo/在线付款成功 → 原生订单确认 → ERP 任务自动排队 → 创建并查询核对 ERP 单据 → Odoo 显示 ERP 编号。

### 银行转账、定金或约定付款条件

继续使用现有 Payments & PI 和财务实际到账审核。达到原有确认订单条件时才触发传单。比如 30% 定金使订单确认，则传**整张订单全部商品和总金额**，不是只传 30%；之后支付 70% 尾款不会再新建第二张 ERP 订单。

### 客户先提交、等待运营调整

报价仍未确认时不传 ERP。运营改好商品、数量、运费、税费，必要时打开报价单 **Other Info → Check ERP Order Setup** 预检客户币种和行税。按钮成功不代表已经传单，也不替代全部后台接口校验。

最终按原有付款/确认规则成为正式销售订单后，冻结当时的金额、数量、汇率、组织和日期，再排队传单。

### 查看结果

在销售订单 **Other Info** 中查看 **ERP Submission、ERP Order Number、ERP Order ID**。已传成功显示 **Created in ERP**；改过订单则出现 **ERP Change / Cancellation Requires Review**。

如果显示 **Submitted / Outcome Pending Verification**，表示已尝试提交、结果仍在核验，不等于 ERP 没有订单。系统按现有退避规则自动回查，达到次数上限后显示 **Action Required**。在对应 **ERP Integration Jobs** 任务中点击 **Recheck ERP Result** 可再次核验；不会再次新增。请不要另建一张替代订单。

网络恢复后，系统找到原 ERP 单号并核对客户、销售组织、负责人、币种、商品及金额，全部一致才更新成功。若长期查不到或信息不一致，请将 ERP Order Number 提供给负责人员核对。由于提交记录在请求前保存，即使极端情况下请求未真正发出，也不会盲目重发，需要人工确认处理。升级前已准备请求的旧任务同样保守地只核验。

有 B2B Integration Manager 权限的员工可以打开该订单的 ERP Jobs，查看任务结果和安全摘要。只显示其允许销售公司的任务，不向客户暴露接口请求或密钥。

## 7. 常见异常怎么处理

| 情况 | 操作 |
| --- | --- |
| Pending | 等后台任务；任务先准备并保存不可变请求，之后才发送。手动 Process Now 第一次可能只完成准备，这是正常的 |
| Failed | 查看 Last Error。网络/结果暂未查到可等待重试，或按已有任务的 Retry / Process Now 操作 |
| Dead Letter / Action Required | 先处理客户映射、负责人、币种、税务、物料或金额问题，再在同一任务重试；不要自行复制订单反复发送 |
| ERP 已收到、网站未收到响应 | 系统按同一 ERP 单号查找并核验，再决定是否需要发送，始终使用相同防重键 |
| 已存在 ERP 单但核对不一致 | 停止重复创建，人工核对现有 ERP 单；不能“再点一次生成另一张” |
| 已确认订单被改单/取消 | 系统创建人工核对活动并标记，ERP 不自动改单或取消；后续接口规则确定后再接入 |

若已冻结请求中存在需要改变的业务金额，不可直接修改后台 JSON 或假装清空任务重发。当前阶段应人工协调处理旧 ERP 单并保留审计记录。

## 8. 本次接口规则速查

| 内容 | 规则 |
| --- | --- |
| 销售/开票/库存组织 | 全部跟随配置的销售组织；本期仅 999 |
| 交易类型 / 汇率类型 | KC 库存销售 / 03 |
| 单号、防重键 | 系统生成 PH-T- 开头单号和稳定 32 位防重键 |
| 单据、汇率日期 | 原生订单确认当天，按中国时区；重试不会改成另一日期 |
| 客户、业务员、部门、开票客户 | 已绑定 ERP 客户及目标组织下的默认资料 |
| 原币 | ERP 客户交易币种，未维护则 USD；须等于 Odoo 订单币种 |
| 本币、汇率 | CNY；USD 用配置值，CNY 用 1 |
| 电源插头 / 工作电压 / 是否打托 | 无（00）/ 无（00）/ 是 |
| 明细 | 产品/变体 ERP 物料编码、基础单位数量、折后不含税单价、原生税额和含税金额 |
| 计划发货 / 销售类型 | 确认日后 90 个自然日 / 普通销售 |
| ERP payMoney | 订单含税总额，不是已收款金额；本期不对接财务到账记账 |

操作说明不会自动代替生产配置。正式使用前须维护真实客户的 ERP 默认业务员/部门、原币、产品单位和运费料号，并完成正式组织切换验收。

### 默认业务员如何确定

按目标销售组织查询ERP客户明细，使用该组织下唯一的默认专管业务员和部门，不使用Odoo登录员工或品牌预设人员代替。客户由 `global00` 管理、在 `999` 使用也可以正常识别；接口是否返回组织范围表无需运营处理。

若负责人未设置、默认负责人有多个或返回组织矛盾，系统会阻止传单并提示先核对ERP客户配置。修正后重试同一任务，不必复制订单。已冻结的请求不会随客户资料变化而静默改写；订单创建后的查回核对也包括业务员和部门。

## 9. 客户查看供应及发货进度

本节包含2026年10月12日新增的手动刷新功能。它只查询用友报表，不创建生产单、出库单，不重新推送销售订单，也不改动财务或库存。

### 客户怎样操作

1. 登录网站，进入 **My Account → Orders**，打开一张已确认的订单。
2. 点击订单详情页的 **Order Progress**，进入原来的 `erp-status` 页面。
3. 页面按商品展示卡片：订购数量、已发数量、未发数量，以及 **Supply Order Date、Expected Completion Date、Warehouse Receipt Date、Dispatch Date** 四个日期。
4. 首次查询或旧缓存超过30分钟时，页面先展示已有内容及 **Updating order progress…**，随后自动更新，无需反复点击。后台通常很快开始处理；排队或ERP响应慢时可能需要等待。
5. ERP刚更新但网页仍显示旧数据时，点击最近成功更新时间旁的 **Refresh Progress**。这会跳过正常的30分钟缓存，重新请求查询；按钮显示 **Refreshing…** 时不要重复点击，原有商品内容会保留。
6. 成功查到变化显示 **Progress updated.**；成功回查但内容相同显示 **Progress checked. No new updates.**。只有后台真正完成了一次新查询，才会显示查询成功提示；刷新网页本身不算查询成功。
7. 点 **Back to Order** 返回订单详情。

新订单刚传入ERP，不代表已经有供应或出库记录。查询成功但报表尚无记录时，日期显示 **Not available yet**，已发及未发数量显示横线，不将未知数量当成0，也不伪造生产或发货状态。

### 刷新规则

- 没有人访问进度页时，不按小时查询全部订单。使用Odoo原生计划任务处理已经被客户或员工请求的查询；任务定时醒来不等于每次都会调用ERP。
- 同一订单的并发访问合并为一次请求。成功缓存复用30分钟；临时网络错误冷却5分钟；字段、数量或组织等需核验的问题冷却30分钟。冷却结束后再次进入页面才请求下一次查询，不在后台无限重试。
- 手动刷新只跳过正常成功缓存。同一订单最多每60秒请求一次新查询，该限制由服务器执行、所有联系人及后台员工共用；网页会显示剩余等待时间并自动恢复按钮，不必刷新整个页面。
- 已排队或正在查询时复用同一个请求。手动刷新不能绕过网络失败冷却、订单归属权限、已取消或改单待核验状态，也不能绕过ERP连接身份校验。
- 页面等待最多约90秒，期间只检查Odoo本地结果，不直接访问ERP。超时或失败时保留最后一次成功的数据和更新时间，显示英文提示；客户不会因ERP查询异常跳入原生错误页。

### 运营查看异常

1. 打开 **Sales → Orders → Orders**，进入对应销售订单。
2. 切到 **Other Info**，查看 **ERP Submission、ERP Order Number、ERP Order ID**，先确认销售订单已经成功传入ERP。
3. 查看 **Order Progress Update、Last Successful Progress Update、Last Progress Attempt、Progress Update Error、Progress Data Notes**。没有成功更新时间表示尚未获得有效的进度快照；Data Notes用于区分数量尚未提供和多行统计歧义，不向客户显示。
4. 有 **B2B Integration Manager** 权限的员工可以点击 **Refresh Order Progress** 请求查询。该按钮采用与客户按钮一致的手动规则：可跳过正常30分钟缓存，但不能绕过60秒防重和错误冷却。
5. 若错误涉及报表字段或数量，交给ERP维护人员核对 `xinquanliucbiao`；若网关暂时超时，等待冷却后再次进入即可。不要为了查进度点击销售订单的重推，也不要复制订单。

### 多商品 多供应单与改单

系统以ERP销售订单明细ID对应Odoo商品行，不依赖页面行号或产品名称。商品名称、SKU仍显示网站的资料；ERP内部编号和错误详情不暴露给客户。

一条商品行关联多条供应记录时，会显示多个日期及可展开的 **View supply progress details**。当前报表没有确认多供应单的累计数量口径，因此不直接求和或取最大值；客户看到简短的 **Shipment quantity pending**，具体歧义记录在后台 **Progress Data Notes**，避免重复统计。

数量尚未提供属于正常等待，显示 **Awaiting shipment updates**，有效日期仍可显示。已移除原先笼统的“shipment total … requires verification”长提示。未知数量不会擅自填写0；ERP一旦返回有效累计数量，刷新成功后即可按实际数量显示 **Partially shipped** 或 **Fully shipped**。

已传ERP的订单如果在Odoo改单，原有ERP进度不冒充新版订单进度，页面提示等待运营确认；本阶段仍不自动调用ERP改单接口。已取消订单不再请求查询。运费及其他服务产品显示 **No shipment required**，不制造实物发货进度。

安装或升级 `b2b_yonyou` 会自动加载页面、资产和计划任务；沿用已有C4连接配置和接口授权，不另开客户预览端口。Odoo.sh部署后仍需确认该应用具有报表查询接口权限。
