# Partner Hub 银行转账付款：逐步操作手册

更新日期：2026-09-14  
适用版本：19.0.1.16.3  
读者：运营、财务、仓库及需要指导客户的工作人员。

本手册使用当前英文界面上的按钮和字段名称，中文解释紧跟其后。用于替代此前《银行转账付款功能操作指南》。业务操作依据本地人工验收记录；会计基础配置由有配置权限的会计管理员执行，不要求普通运营人员配置科目。

## 先找到你现在要做的事

| 你现在的任务 | 看哪一节 | 谁来操作 |
| --- | --- | --- |
| 公司第一次使用银行收款，还没配银行和品牌 | 第1节 | 会计管理员＋财务 |
| 给某个客户指定品牌、定金比例或账期 | 第2节 | 运营／B2B Manager |
| 教客户下单、下载PI、上传付款截图 | 第3节 | 客户，运营可按文中步骤指导 |
| 看到了客户付款待办，不知道下一步怎么做 | 第4节 | 财务／B2B Finance |
| 截图不清楚、客户需要补材料 | 第5节 | 财务＋客户 |
| 需要收尾款、安排发货 | 第6节 | 财务＋仓库 |
| 想更换某张订单的收款账号 | 第7节 | 运营／B2B Manager |
| 客户改单后需要退款 | 第8节 | 运营＋财务 |
| 对账、开票、操作报错或找不到记录 | 第9、10节 | 财务或对应工作人员 |

## 所有人先看：保存、选择、查找怎么操作

### A. 后台的“保存”在哪里

很多后台页面没有写着Save的大按钮。修改字段后，在页面上方、记录名称旁边找保存图标；鼠标停上去会显示 **Save manually**。点击它保存。

保存后重新打开同一条记录，确认刚才填写的内容仍在，才算这一步完成。弹窗如果显示 **Save & Close**，点它保存并关闭弹窗。**Discard all changes** 是放弃未保存的修改，不是保存。

### B. 下拉字段不是输入文字就完成了

点击字段 → 输入要找的名称 → 点击下拉结果中的那一项 → 再保存。只输入名称但没有点选结果，可能没有真正关联记录。

多选字段选中后会显示名称标签。找不到记录时用 **Search more...** 搜索更多结果，不要随意新建一条同名记录。

### C. 找不到菜单时不要换成无关菜单操作

运营和财务看到的菜单不同。**B2B Manager不自动等于B2B Finance**；财务也不自动拥有会计配置管理员权限。

请让管理员检查原生 **Settings → Users** 中该账号的权限。不要为了日常审核直接授予系统管理员全部权限。

### D. 三件事不能混为一谈

- 客户上传截图：只是提交了材料，不是已经到账。
- 财务确认到账：系统才增加已收款，并重新判断订单是否满足付款条件。
- 仓库完成出库：客户才会看到实际发货结果。**Shipment Allowed不等于Shipped。**

## 1. 第一次配置：银行账户与品牌

这一节通常只在首次上线、增加银行或增加品牌时做。日常收到客户付款时直接看第4节，不用重复配置。

### 1.1 先确认银行账户已经在系统里建立

**谁操作：有原生Accounting配置权限的会计管理员。**

“银行日记账”可以理解为系统里的一个银行收款配置。品牌选择的是这条配置的名称，不是在品牌页面直接填写银行卡号。

**怎么进入**

1. 从后台应用入口打开 **Accounting**。
2. 点击 **Configuration**。
3. 点击 **Journals**。
4. 先查找现有银行记录。已经有对应实际账号时，打开核对，不要再建重复账户。

**没有对应账户时怎么填**

1. 点击 **New**。
2. 给记录起一个容易识别的名称，例如“LUCKY TONE－银行简称－USD”。这只是命名示例，不是实际收款资料。
3. **Type** 选择 **Bank**。
4. **Company** 选择我们实际收款的销售法人，不是客户公司，也不是新建一个品牌法人。
5. **Currency** 明确选择收款币种。留空时会按公司本位币判断，不要把留空理解为自动支持全部币种。
6. 填写或关联真实银行账号。核对户名、账号、银行名称及SWIFT/BIC；部分资料需要打开关联的银行账号／银行记录填写。
7. 会计人员检查入账付款方式及 **Outstanding Receipts** 科目；需要银行退款时，同时检查出账付款方式和待付款科目。普通运营不要猜测科目。
8. 保存，记下这条银行日记账的名称。

**做完应看到什么**

重新打开Journals中的该记录，能看到保存的Bank类型、币种和实际账号。后面在品牌页面按这个记录名称选择。

**卡住怎么办**

- 没有Configuration菜单：交给会计配置管理员，不要从品牌页硬建账户。
- 只有Bank、Bank (2)这类名称：先打开核对账号，让会计改成可识别的名称再使用。
- 看到UAT、TEST-ONLY、DO NOT TRANSFER：这是演示账户，不能用于正式收款。

### 1.2 把银行账户关联到一个品牌

**谁操作：B2B Finance。**

**怎么进入完整品牌页面**

1. 打开 **B2B Management**。
2. 点击上方 **Operations**。
3. 点击 **Brand Receiving Accounts**。
4. 进入后看到的是 **Product Brands** 品牌列表，这是正常的，不是走错页面。
5. 找到需要配置的品牌，例如 **LUCKY TONE**。
6. 点击该行右侧的 **View** 按钮，鼠标提示是 **Open in form view**。

**重要：不要只点击品牌名称。列表支持直接编辑名称等字段，只点名称可能不会打开完整页面。窗口窄时向右滚动列表找View。**

**进入后怎么关联**

1. 在品牌完整页面向下找到 **Receiving Accounts**。
2. 找到下面的 **Receiving Bank Journals** 字段。
3. 点击它右侧的空白输入位置；已有标签时，点击标签后面的空白处。
4. 输入第1.1节记下的银行日记账名称。
5. 点击下拉列表中的正确记录；结果不全时点击 **Search more...**。
6. 看到一个带日记账名称的标签后，点击页面上方 **Save manually** 保存。
7. 返回品牌列表，再点同一品牌右侧 **View**，确认标签仍在。

**做完应看到什么**

Receiving Bank Journals中显示所选银行的名称标签。这表示这个品牌允许使用该银行，但还需要在第2节把客户指定到这个品牌。

**卡住怎么办**

- 看不到Receiving Accounts：确认已经点View进入完整页面，并且账号有B2B Finance权限。
- 下拉框没有目标银行：回第1.1节检查是否已保存、Type是否为Bank，以及当前账号是否能访问对应法人。
- 下拉没有Create／Create and Edit：这是正常限制；这里不能新建银行。
- 输入文字但没有标签：尚未点选下拉结果。
- 保存提示无权修改品牌：纯财务只维护收款关联，不要同时修改Name、Tagline、Logo等品牌内容。

可以关联多个获准账户，但建议每个品牌、每种币种先只放一个常用账户。关联多条并不代表客户会看到多个账号供其自由选择；订单会选定具体账户。

### 1.3 没有指定品牌的新客户使用哪个账户

**谁操作：网站设置管理员。**

1. 打开 **Website → Configuration → Settings**。
2. 多网站环境先确认当前设置的是要收款的网站。
3. 在Partner Hub相关设置中找到 **Default Collection Brand**；可用浏览器页面查找此英文名称。
4. 选择默认品牌，使用设置页面的 **Save** 保存。
5. 确认默认品牌已经按第1.2节关联了有效银行。

这是“客户公司没有指定品牌”时的后备值。已经指定品牌的客户仍使用自己的品牌配置。

## 2. 运营：给客户指定品牌和付款方式

**谁操作：B2B Manager。准备好：客户公司名称、应该使用的品牌、双方约定的付款比例。**

### 2.1 打开正确的客户记录

1. 打开后台 **Contacts**。
2. 搜索客户公司名称。
3. 打开客户的**公司记录**，不要打开公司下面某个人的联系人记录。
4. 点击 **Partner Hub** 页签。
5. 找到 **Collection and Brand** 区域。

### 2.2 填写并保存

1. **Account Brand**：选择第1节配好的收款品牌。
2. **Collection Terms**：选择双方约定的付款方式。
3. 点击上方 **Save manually**。
4. 重新打开公司记录，确认两个字段都已保存。

公司的个人联系人下单时沿用公司设置。不需要给每个联系人重复填。修改这里不会自动替换已经提交订单的配置。

### 2.3 不知道选哪种Collection Terms时，看这张表

| 与客户的约定 | 选择类型 | 什么时候可以确认订单／安排生产 | 什么时候可以出库 |
| --- | --- | --- | --- |
| 全款到账后再做货 | A | 收齐100% | 收齐100% |
| 先收30%定金、发货前收70% | B，30/70 | 累计收到30% | 累计收到100% |
| 先收20%定金、发货前收80% | B，20/80 | 累计收到20% | 累计收到100% |
| 可以先做货，但发货前收齐 | C | 可先确认 | 收齐100% |
| 可以先做货、发货，按账期收款 | D，并配置原生发票账期 | 信用检查通过 | 信用检查通过 |
| 其他特殊约定 | E | 按配置比例 | 按配置比例及其他检查 |

“出库前100%”是累计总额，不是在定金之外再付100%。如果付款方式未设置，按A类处理。

### 2.4 下拉没有所需比例时

1. 打开 **B2B Management → Operations → Collection Terms**。
2. 先检查是否已有相同条款；没有才点 **New**。
3. **Name**：写清含义，例如“30% Deposit / 70% Before Shipment”。
4. **Category**：按第2.3节选择A、B、C、D或E。
5. **Required % Before Production**：填写生产前累计应收百分比，例如30。
6. **Required % Before Shipment**：填写出库前累计应收百分比，例如100，而不是70。
7. **Invoice Payment Terms**：允许欠款出库时，必须选择原生发票账期，例如已配置的Net 30。
8. **Block Overdue**：按已批准的信用管理要求设置。开启后逾期应收可能阻止放行。
9. 保存，再回客户公司选择刚建的条款并保存。

生产前比例不能大于出库前比例。A必须100/100、B为部分定金/100、C为0/100、D为0/0；不要为绕过提示随意更换类型。

### 2.5 配好后怎么检查

用一张新提交的订单查看 **Collections & PI**，核对品牌、银行和比例；再查看客户页面的银行说明及下载的PI。旧订单保留快照，不能只刷新旧订单就认定新配置没有生效。

## 3. 客户：提交订单、下载PI、上传转账凭证

以下步骤可直接用于指导客户。正常客户凭证必须是实际转账材料，不是演示图片。

### 3.1 客户第一次提交银行付款订单

1. 登录网站。
2. 将商品加入购物车，核对数量。
3. 点击 **Checkout**，按现有结账步骤核对地址和配送信息。
4. 到付款页后，找到 **Bank Transfer / Customer Payment Terms** 区域。
5. 点击 **Submit Order — Pay by Bank / Agreed Terms**。
6. 等待页面进入 **Payments & PI**，记下页面显示的订单号。

**成功标志：**能看到Payment Summary和Bank Transfer Instructions。不要再次点击下单去“尝试生成正式订单”；付款条件未满足时保留为报价是正常的。

如果需要先让运营改商品或费用，应使用原有的订单审核流程。运营审核未结束时，不要绕过审核转账。

### 3.2 客户以后从哪里回到付款页

1. 打开 **My Account**。
2. 进入 **Orders**。尚未确认的报价可切到 **Quotations**。
3. 找到对应订单号，点击 **View Details**；若所在列表以订单号提供详情链接，点击该订单号。
4. 在订单详情的操作区域点击 **Payments, Bank Transfer & PI**。
5. 进入 **Payments & PI**。

注意：详情按钮名称较长，进入后页面标题较短，二者是同一个功能，不要再找一个叫“银行转账”的独立应用。

### 3.3 先下载PI，再去银行付款

1. 在 **Bank Transfer Instructions** 核对收款户名、账号、币种和Payment reference。
2. 点击 **Download Current PI**。
3. 将下载的PI交给客户公司财务申请付款。
4. 在实际银行完成转账，备注中填写对应订单参考号，方便核对。

**如果没有账户或下载按钮，而是提示联系工作人员：**先找运营配置账户，不使用其他订单的账号替代。

PI只是付款申请文件，不是到账证明或正式税务发票。银行付款完成后还要做下一步。

### 3.4 上传付款凭证

在同一页向下找到 **Upload Payment Proof**。

| 按页面顺序填写 | 应该填什么 |
| --- | --- |
| Transfer Amount（后面显示币种） | 本次付款申报金额，必须大于0；不是整单金额，也不是累计已付款金额 |
| Transfer Date | 实际转账日期，不能是未来日期 |
| Bank Reference | 银行流水号或可追踪的交易参考号 |
| Proof | 点击文件选择框，选择实际凭证文件；支持PDF、PNG、JPG，最多8MB |
| Additional Information | 必要说明，例如“定金”“尾款”或实际转账币种、手续费情况 |

1. 填完后先确认文件名称已经显示在文件框中。
2. 点击 **Submit Payment Proof**。
3. 到下方 **Bank Transfer History** 看是否出现新记录。

**成功标志：**出现BTR编号，状态为 **Awaiting Finance**。此时Confirmed Payments没有增加，是正常的，财务还没确认。

若提交报错，按提示修正后重新选择文件再提交。若网络慢，先查看历史有没有新记录，不要把同一笔钱反复重新申报。

### 3.5 客户看不懂金额时怎么解释

| 页面名称 | 对客户的解释 |
| --- | --- |
| Order Total | 这张订单总共多少钱 |
| Confirmed Payments | 财务已确认的净收款，实际退款会影响它 |
| Evidence Awaiting Review | 已交截图但尚未审核的申报金额，不是已经到账 |
| Remaining Balance | 还剩多少钱没付 |
| Required for Current Stage | 为达到当前生产或发货付款要求，至少还需付多少 |

账期客户“当前需付0”不表示免付款，应按正式发票到期日付清剩余金额。

## 4. 财务：一笔客户转账怎么审核

**谁操作：B2B Finance。必须先确认银行实际到账，再操作确认。**

这一节需要完成“两次确认”：先在原生付款单登记到账，再回客户凭证记录把金额分配到订单。不要只做第一步。

### 4.1 找到客户刚提交的凭证

1. 打开 **B2B Management**。
2. 在 **Dashboard** 点击 **Bank transfer reviews** 数字卡片。
3. 进入 **Bank Transfer Reviews** 列表。
4. 找到对应订单的那一行，点击 **BTR编号** 打开记录。

也可以从 **Operations → Bank Transfer Reviews** 进入。

**此列表默认筛选Awaiting Finance。已审核、已拒绝的记录会从这个列表消失，不是被删除。**查旧记录时，先移除搜索栏中Awaiting Finance筛选旁的×，再查BTR编号或订单号。

### 4.2 核对材料和真实流水

1. 记录顶部是BTR编号；正文查看 **Order**，确认对应订单。
2. 查看 **Customer Declared Amount**、**Transfer Date**、**Transfer Reference** 和 **Customer Note**。
3. 在 **Evidence** 看附件名称；需要看图片时，点击记录沟通区的回形针按钮展开Files，再点击图片缩略图打开查看器。关闭预览用右上角×。
4. 到实际银行渠道核查资金是否到账、付款人、币种和金额。

不要仅凭截图确认。客户申报300、银行只到账295时，实际收款应按295登记，差额交给财务处理。

### 4.3 先判断：原生收款单是否已经存在

**已经登记过这笔流水：**

1. 点击 **Native Bank Receipt** 字段。
2. 搜索已有付款单编号并选中。
3. 核对客户、日期、金额、银行，确认是同一笔流水。
4. 直接继续第4.5节，不要再次创建收款单。

**还没有登记：**继续第4.4节。

### 4.4 新建原生收款单

1. 在BTR记录顶部点击 **Register / Open Receipt**。
2. 新收款记录会带入当前客户和申报金额。先逐项核对，不要直接接受默认金额。

| 付款单内容 | 怎么检查 |
| --- | --- |
| Receive／收款方向 | 这里是客户付给我们，应为Receive，不是Send |
| Customer | 当前客户公司，不是其他客户 |
| Amount | 银行实际到账金额 |
| Date | 实际到账记账日期，由财务按流水确认 |
| Journal | 实际收到这笔钱的银行日记账 |
| Currency | 实际收款币种 |
| Payment Method | 使用财务已配置的对应入账方式；手工登记使用已配置的手工方式 |

3. 保存并点击原生付款单上的 **Confirm**。
4. 如果当前新建弹窗先提供 **Save & Close**，先保存关闭，再从原BTR点击 **Register / Open Receipt** 打开已经保存的付款单，完成Confirm；不要另建第二张付款。
5. 记下生成的原生付款编号。

**成功标志：**原生付款不再是草稿，有已过账的会计分录。付款状态可能是 **In Process**，不是必须等到显示Paid才返回凭证审核。

这不是系统替你向银行收钱，而是记录银行已经收到的钱。

### 4.5 返回BTR并确认订单收款

1. 回到原来的BTR记录。若打开付款后找不到返回位置，重新进入 **B2B Management → Operations → Bank Transfer Reviews**，按记下的BTR或订单号打开同一条记录。
2. 确认 **Native Bank Receipt** 已显示刚才那张原生付款单。
3. 看 **Receipt Currency**，确认下一个分配金额使用什么币种。
4. 在 **Allocated Amount (Receipt Currency)** 填写本次用于这张订单的金额。例如实际到账300且全部付本单，就填300。
5. 在 **Review Note** 填写必要的核对说明。如果实际到账银行与订单指定银行不同，必须说明原因。
6. 点击页面顶部 **Confirm Actual Receipt**。
7. 系统询问是否核实真实银行资金时，确认无误再点 **Ok**。

**成功标志：**

- 顶部状态变为 **Receipt Confirmed**。
- **Confirmed Credit to Order** 显示本次确认到订单的金额。
- 出现审核人和审核时间，待办完成。
- 客户重新打开Payments & PI后，已收款增加、余额减少。

如果报错，先按第10节检查；不要反复新建原生收款单解决报错。

### 4.6 实际到账金额不刚好时

| 情况 | 财务应怎么做 |
| --- | --- |
| 只收到一部分 | 只确认实际分配金额；让客户补余款 |
| 收款超过本单余额 | 本单只分配剩余应付额，多出部分保留为客户未分配余额 |
| 一笔流水支付多个订单 | 使用同一原生付款，在对应凭证中分别分配；累计不能超过流水总额 |
| 收到其他币种 | 原生付款记实际币种，分配字段也按该币种；系统按付款日期汇率折算到订单币种 |
| 是线上支付生成的付款记录 | 不再当作银行转账审核一次，避免重复计款 |

手续费、汇差和会计核销由财务按原生会计流程处理，不通过虚增金额“补齐”。

## 5. 财务退回材料后，客户怎么补交

### 5.1 需要补材料

**财务操作：**

1. 打开待审核BTR记录。
2. 在 **Review Note** 写清缺什么，例如“请补充显示交易参考号的清晰凭证”。客户会看到这段内容，建议用英文。
3. 点击顶部 **Request More Information**。
4. 确认状态变为 **More Information Required**。

**客户操作：**

1. 回到同一订单的 **Payments & PI**。
2. 在 **Bank Transfer History** 查看财务原因。
3. 重新填写 **Upload Payment Proof** 表单，选择新凭证。
4. 点击 **Submit Payment Proof**，确认产生一条新的Awaiting Finance记录。

财务按第4节审核新记录。旧记录会保留，不需要也不应删除。

### 5.2 不认可该凭证

1. 财务在 **Review Note** 写清原因。
2. 点击 **Reject**。
3. 状态变为 **Rejected**，客户能看到原因。

退回、拒绝和待审核材料都不算已收款。客户重新提交时，财务仍须检查是否已有原生流水，防止重复登记。

## 6. 收尾款与发货：以1,000美元、30/70为例

### 6.1 定金阶段

1. 客户按第3节下单、下载PI、转账300并上传凭证。
2. 财务按第4节登记Receive 300、确认分配300。
3. 客户页面应显示已收300、剩余700。满足生产门槛，但尚未满足付清出库条件。

### 6.2 尾款阶段

1. 运营提醒客户需要付尾款700。
2. 客户进入**原订单**的Payments & PI，不重新下单。
3. 按当前银行指引转账700，再上传一份尾款凭证。
4. 财务对新BTR按第4节登记和确认本次700。
5. 核对客户页面：已收1,000、余额0、待审核0。

### 6.3 仓库完成实际出库

**谁操作：有原生库存权限的仓库人员。**

1. 打开 **Inventory**。
2. 进入出库作业列表；在搜索框输入运营提供的订单号，并选择按 **Source Document** 搜索。
3. 打开对应 **WH/OUT/...** 出库单。
4. 核对来源订单、商品和实际数量，按原生库存要求处理批次、序列号等内容。
5. 点击 **Validate**。
6. 确认出库状态为 **Done**，再让客户刷新订单详情查看 **Shipped**。

如果Validate提示付款／信用／改单审核不满足条件，把订单号交给运营和财务查，不要绕过检查。满足付款门槛也不保证所有其他放行条件都已满足。

## 7. 运营更换某张订单的银行账户

**谁操作：B2B Manager。先确认新银行已经按第1节关联到目标品牌。**

1. 打开后台 **Sales**，在报价／订单列表搜索该订单号并打开。
2. 点击 **Collections & PI** 页签；这是网站订单的收款配置页签，不是原生发票的Other Info。
3. 填写 **Reason for Configuration Change**，解释为什么更换。
4. 如需换品牌，选择 **Order Brand**。
5. 在 **Receiving Bank Journal** 选择获准的新银行日记账。
6. 点击上方 **Save manually**。
7. 在同页核对银行说明已更新。
8. 请客户重新进入Payments & PI，点击 **Download Current PI**，核对新账户后再付款。

有待审核凭证或处理中支付时，系统会禁止更改；先让财务处理相关记录。不要为了更改账户直接删除客户凭证。

已确认订单的比例不能在这里随意改。草稿／报价上的 **Apply Collection Configuration** 用于按当前选择重新取配置，不是到账确认按钮。

客户页面 **Issued PI Versions** 中保留旧PI。新旧银行不同是历史版本记录，不要删除旧文件；指导客户本次使用最新PI。

已经开发票时，财务另行核对 **Accounting → Customers → Invoices → 对应发票 → Other Info → Recipient Bank**。不要假设改订单会自动改好历史发票，更不要静默覆盖已签发文件。

## 8. 已付款后改单与退款

### 8.1 运营先完成提案，不直接改掉原支付记录

1. 客户在订单的 **Request an Order Change** 入口提交需求。
2. 运营进入 **B2B Management → Operations → Order Changes**，打开对应申请。
3. 点击 **Start Review**，再点 **Edit Proposed Order**。
4. 在提案中调整商品、数量或价格，点 **Save & Close** 保存返回申请。
5. 点击 **Send to Customer**。
6. 客户在My Account的 **Order Changes** 查看提案，选择 **Accept Revised Order** 或 **Decline Proposal**。

不要只改提案后退出而不Send to Customer；客户这时还没有收到可接受的正式提案。

### 8.2 看清实际需要退多少钱

| 实际已收 | 修改后总额 | 处理 |
| --- | --- | --- |
| 300 | 800 | 不退款，还需付500 |
| 300 | 200 | 实际退100，不是退原订单的全部降价差额 |

客户接受后需要退款的申请进入 **Finance Review**。正式订单号不因这次修订换号。

### 8.3 财务登记银行退款并完成申请

1. 核对申请显示的实际应退金额。已有正式发票的调整先按财务要求处理贷项或其他会计文件。
2. 在实际银行完成退款。
3. 打开 **Accounting → Customers → Payments**，点击 **New**。
4. 方向选择 **Send**，核对Customer、实际退款金额、币种、日期、Journal及付款方式。
5. 保存并 **Confirm**，确保有已过账分录，记下原生退款付款编号。
6. 回到 **B2B Management → Operations → Order Changes** 的同一申请。
7. 在 **Bank Refund Payment** 选择刚登记的退款。
8. 填写 **Finance Reference** 和财务说明。
9. 点击 **Finance Complete**。
10. 确认申请 **Completed**，客户页面净收款与新订单总额匹配。

仅填一个文字参考号不能完成退款。不要用其他客户、其他金额或已被使用过的退款单。完成后不能换一张退款证据。

如果退款实际走线上渠道，应使用成功完成的原生 **Refund Transaction**，不要同时选择银行退款重复扣款。Finance Complete本身不会替你向银行或支付平台发起退款。

## 9. 财务还需要做的原生会计工作

到账审核不等于完成会计对账。

1. 在原生Accounting核对银行流水、客户付款与发票。
2. 将付款核销到对应发票；同一客户有多张订单时，不把其他订单的未分配款随意加到本单。
3. 按账套处理手续费和汇兑差额。
4. A／B／C按正常销售开票流程开正式发票，不用PI代替。
5. D／允许欠款出库的E类在出库时按原生开票政策产生应收，财务核对发票金额和到期日。分批开票仍受商品开票政策约束。
6. 对账期客户跟踪到期应收；“允许先发货”不等于无需收款。

发票网页显示 **Invoice Preview** 时，表示网页预览，不是订单PI。是否已过账请看原生发票状态。正式文件仍按原生发送／生成流程处理。

撤销原生收款可能使后续出库再次不满足条件，但不会自动撤销已经完成的实物出库。历史凭证和退款记录保留审计，不删除来“清理状态”。

## 10. 操作卡住时，按现象查

| 页面现象或提示 | 先做什么 | 不要做什么 |
| --- | --- | --- |
| Brand Receiving Accounts里看不到收款字段 | 点品牌行右侧View，完整表单底部找Receiving Accounts | 不在品牌名称单元格输入银行账号 |
| 找不到目标银行 | 在Journals检查已保存的Bank类型记录，再回品牌下拉选择 | 不随便选择Bank或演示账户 |
| 没有上传凭证区域 | 查看是否已付清、银行是否配置、订单是否取消或仍待运营审核 | 不另下重复订单 |
| 提示文件格式／大小错误 | 重新选择PDF/PNG/JPG，非空且不超过8MB | 不只改文件后缀伪装格式 |
| 提示日期或参考号有误 | 填实际日期、银行参考号，再重新选择附件 | 不填写未来日期 |
| 上传后已收金额还是0 | 等财务完成原生收款登记及Confirm Actual Receipt | 不把待审核金额当实际收款 |
| Select the actual native bank receipt first | 回Native Bank Receipt关联真实原生付款 | 不只填Review Note反复点确认 |
| Post the native bank receipt... | 请财务核对付款分录过账和Outstanding Receipts配置 | 不手改状态冒充过账 |
| Allocate a positive amount... | 核对分配金额是否正数，累计是否超过原收款 | 不重复新建相同流水 |
| Allocate only the outstanding order amount... | 本单只分配剩余未付额，多余款留客户余额 | 不强行把超付款全计入本单 |
| 已审核记录不见了 | 移除Awaiting Finance默认筛选，再搜索BTR编号 | 不重新提交一份来补记录 |
| 已收定金仍不能发货 | 查尾款、信用和改单审核；定金放行生产不等于放行出库 | 不绕过Validate拦截 |
| 换银行保存失败 | 查是否有待审核凭证、处理中支付及变更理由 | 不删除付款记录 |
| Finance Complete不能点成完成 | 查有效原生退款、客户、金额、币种及是否重复使用 | 不只填文字退款号 |

## 11. 上线前由负责人确认

- 真实公司名称、地址和英文报表资料正确，示例网址已清理。
- 实际品牌Logo、银行账号、收款币种和默认品牌已核对。
- 客户公司已分配正确品牌及付款条款。
- 操作人员分别能找到自己负责的菜单，邮件通知可正常发送。
- 不使用UAT／TEST-ONLY测试账户收款。
- Git代码更新不会自动复制本地银行、品牌关联或报表配置；Odoo.sh目标数据库要重新核对。

本手册对应当前应用功能，不表示真实银行、线上支付服务商退款或外部ERP已经完成生产联调。当前实际出库在Odoo内操作。
